# 资产检索与补全规范（技能共用）

适用技能：`h3-drama-producer`、`h3-video-replicator`，以及任何需要「人物三视图 / 场景 / 道具」参考图的生产技能。
各技能 SKILL.md 只写本技能的特有规则，通用检索与补全流程一律以本文件为准。

**占位符约定（全文禁止写死绝对路径）**：

| 占位符 | 含义 |
|---|---|
| `<项目根>` | 当前工作区根目录（各机器不同，运行时确定） |
| `<资源包>` | IP 资产包名（如某小说/某 IP 一包） |
| `<项目>` | 当前项目目录（单个剧/复刻任务的输出目录） |
| `<备用源>` | 某资源包登记的额外资产目录，由用户当场指定或项目《资产清单.md》记录，**不写死在技能文件里** |

## 1. 两层资产体系

| 层 | 位置 | 用途 |
|---|---|---|
| IP 级共享 | `<项目根>\assets\<资源包>\character\`（人物）`scene\`（场景）`props\`（道具） | 跨项目复用 |
| 项目级私有 | `<项目>\scene\`、`<项目>\props\`（及 `<项目>\衔接帧\`） | 本剧情专属 |

**检索顺序一律：项目私有 → IP 共享 → 用户指定目录 / `<备用源>`**。用户当场指定的目录永远最优先。

## 2. 检索流程

### 2.1 角色（人物三视图）

- 命名约定：`人物三视图（{造型}）.png`；面部特写 `特写图.png`；设定卡 `详细信息图.png`
- 检索：对每层资产目录按人物名匹配文件夹，再找三视图文件

  ```powershell
  Get-ChildItem <资产目录> -Recurse -Directory | Where-Object Name -like "*<人物名>*" | ForEach-Object { Get-ChildItem $_.FullName -Recurse -File -Filter "*三视图*" }
  ```

- 找到后**用 Read 工具查看图片内容**，记录实际形象与服装（不看缩略图/联系表）
- **同一人物多张三视图（基础/宫装/校服…）必须先询问用户选哪张**，说明各张差异
- **⚠️ 别名/身份合并检索（强制，IP 改编必查）**：按剧本角色名找不到目录时，**不要立刻判"缺失"、不要凭原著描述自拟造型**——先在 `<项目根>\assets\<资源包>\character\_人物资产索引.md` 里按角色名与剧情关键词全文搜索。IP 资产库常有「同一人物多称谓」，索引条目往往已写明合并关系（实例：「乐上师」即「穆兰圣女」，同人同形）。**同一人物的不同称谓一律复用同一份三视图，不得各建一套**。确认合并后仍按"多张三视图先问用户"处理造型档位。

### 2.2 场景

- 项目私有 `<项目>\scene\` → IP 共享 `<项目根>\assets\<资源包>\scene\`（子目录按标签分类，配套 `场景索引.md` / `场景索引.json`）
- 命名 `场景-{场景名}.png`
- **⚠️ 画风一致性闸门（强制）**：找到候选场景图后必须用 Read 同时查看场景图与本集角色三视图，逐项比对渲染风格（3D 动画 CG / 真人写实照片 / 2D 插画、皮肤质感、光影、景深）。**画风不一致时禁止直接使用，必须停下明确提醒用户**：说明差异、风险（Ref2VA 会以占画面更大的场景图为准统一全片风格，迫使角色脸被"翻译"成场景画风导致五官走形），并给出选项：图生图重绘场景为三视图同画风 / 更换场景 / 用户书面确认接受风险。不得替用户默认放行。

### 2.3 道具

- 项目私有 `<项目>\props\` → IP 共享 `<项目根>\assets\<资源包>\props\`
- 命名 `道具-{名称}.png`

### 2.4 资产映射确认闸门（强制，IP 改编必走）

检索完成后，把「剧本元素 → 复用的资产文件」映射**逐条列给用户确认**再往下走，**尤其**是别名复用、跨角色借用、造型档位选择这几类决策。
**核验有两个层次，别只做第一个**：① **一致性**——成片与参考图是否长得一样（流程可自查）；② **正确性**——参考图本身是不是这个角色在该 IP 里的正确形象（**只能靠用户在出片前确认**）。

### 2.5 输出《资产清单.md》

记录：元素、类别、文件名、路径、**来源层（项目私有 / IP 共享 / 用户指定）**、外观说明、Picture 槽对应关系；**找不到的标"缺失"**，进入补全流程。清单末尾附 Ref2VA 引用示例（`<Picture N>` 与图槽一一对应）。

## 3. 缺失资产补全（生成）

### 3.1 生成前必须审批

整理缺失资产生成计划表给用户：**序号 / 元素 / 类型 / 生成方式（文生图/图生图）/ 生成提示词 / 参考图 / 归档路径 / 预期产出**。用户批准后才生成。

### 3.2 生成提示词要领

- **角色补全**：以最接近的现有造型三视图为参考图，**锁定脸部/发型/身份锚点，仅修改服装**；提示词明确"保持面部、发型、瞳色与参考图完全一致"
- **🚫 禁用 `gemini-3-pro-image` 生成任何图片（用户明令，最高优先级）**：它会把参考图人物重新设计成另一张脸，身份辨识度崩坏。默认模型 `gpt-image-2`；若目标质感达不到，**停下请用户指定模型或路线**，不得自行改用未经认可的模型
- **⚠️ 身份核验第一标准是"是不是同一张脸"，质感是次要的**：核验时把新图与该角色**原始三视图并排比对五官**（眼型、脸宽、下颌、鼻梁），任何一项对不上即判身份失败、作废重来——**不要因为毛孔/雀斑等质感好看就放行**
- **⚠️ 身份漂移的救法：双参考图（同角色多造型必用）**：第 1 张放**原始三视图定身份**，第 2 张放**该角色已通过身份核验的图**（`input.image` 接受数组按顺序传）。第 2 张本身必须先通过与原始三视图的并排比对
- **场景**：文生图空镜不含人物；**必须显式锁定与角色三视图相同的渲染画风**（3D CG 目标写明 "3D Chinese donghua CG animation style … NOT live-action / photorealistic"；真人质感目标照抄资源包的真人质感美术基准 + 反向约束）。生成后 Read 与三视图并排核验画风，不一致即调词重生成
- **道具**：文生图特写，画风与成片目标一致
- **同款道具改文字/换内容**：以已有道具图为参考做图生图，prompt 必须显式声明"只沿用形制、材质与版式，内容必须替换为新内容，不得保留参考图上的任何旧文字"；每个牌面各存一份独立文件
- **⚠️ 一物多面 → 图槽逐段对账（强制）**：同一道具多个牌面/页面文件时，每段图槽键写**完整文件名**（含括号后缀），构建 payload 前逐段人工对账；首发成片特写帧逐字核验牌面文字

### 3.3 生成、核验与归档

1. 任务定义存档 `<项目>\任务记录\任务-{元素名}.json`
2. **人工核验**：角色核身份锚点（发型、瞳色、标志性配饰/妆容）；场景/道具核画风与三视图一致。**核验必须 Read 原图**，缩略图会漏掉脸型漂移、也会把真人质感正常的不完美误判成瑕疵。**同角色多造型时必须与该角色已通过的图并排比对"是不是同一张脸"**
   - 审核拒绝时的重试链：attempt 1 原提示词；attempt 2 前置"一位三十岁上下的成年人物，气质沉稳端正。"
   - **🚫 禁止擅自"抽卡"（用户明令）**：结果不理想想再摇一版/多摇候选，必须先报批（写明摇几次、预估费用、落选图如何处理）；已批准任务内的技术性重试不算抽卡
3. 归档规则：**人物三视图必归 IP 共享** `<项目根>\assets\<资源包>\character\<人物名>\`；场景/道具按通用性判断——跨集跨项目可复用归 IP 共享，本剧情专属归项目私有，拿不准问用户。新 IP 资源包不存在时按 `<项目根>\assets\<IP名>\{character,scene,props}\` 结构创建
4. 同步更新《资产清单.md》与各索引（人物索引用资源包配套同步脚本，不手写；场景类更新 `场景索引.md`）

### 3.4 衔接帧（集间画面连续时，可选）

- 在审批表格中一并生成，"类型"填"衔接帧"：以衔接点涉及的角色/场景参考图做图生图，构图、姿态、光线与上一集末镜头一致，且与下一集开场吻合
- 归档 `<项目>\衔接帧\衔接帧-ENN-ENN+1.png`（项目私有），下一集提示词改用 I2VA 首帧驱动模式

## 4. 跨电脑迁移

技能与资源包会在多台电脑上使用，**任何技能文件都不得写死资产绝对路径**。换电脑后《资产清单.md》里的旧路径可能失效：接手旧项目时先逐条 `Test-Path`，失效条目按"用户指定 → 项目私有 → IP 共享 → `<备用源>`"重新探测并**只更新路径**（人物与外观不变），已过审的剧情/分镜内容不动。
