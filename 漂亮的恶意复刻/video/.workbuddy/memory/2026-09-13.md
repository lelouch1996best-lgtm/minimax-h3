- 构建：写了一个两阶段 ffmpeg pipeline（video/mv_build.py）：
  1. Python 做 BGM onset 检测，把硬切点吸附到音乐重音（9 个卡点）；
  2. Pass1 渲染 24 个片段（韩系调色 eq+colorbalance+柔光 bloom，白场 dip 章节转场）；
  3. Stage A 纯 concat 拼接；Stage B drawtext 标题/章节字幕 + loudnorm(-14LUFS) + 淡出。
- 踩坑记录（ffmpeg 7.1 gyan build）：
  - `-filter_complex_script` 已废弃且有 bug，会报 "No such filter: ''"（空滤镜假错误），必须用内联 `-filter_complex`；
  - xfade 要求恒定帧率 + 相同 timebase：输入需 `[i:v]settb=AVTB,fps=24` 归一化；长 concat 链后接 xfade 仍会报 frame rate 1/0，改用「白场 dip + 纯 concat」绕开；
  - HEVC 源 timebase 1/12288 与默认 1/1000000 不一致是 xfade 报错根因；
  - imageio-ffmpeg 的 pip 包可用来快速获得 ffmpeg 二进制（无 ffprobe）。
- 素材内容：E01-E04 为正片片段，15 个 learned_latent 实验片段（Seoul Art High School 场景：图书馆、天台、雨夜共伞、炸鸡店、篮球场等 K 校园风画面）。

## v2：按用户新提供的 BGM 重剪（无字幕版）
- 用户提供 `video/bgm.mp3`（3:08 / 188s，320kbps 48kHz，中速 ~90BPM），要求重剪且**不要字幕**。
- 时间轴策略：跳过 0-20s 长前奏（该段仅 3 个 onset，剪出来节奏拖），从 20s 能量爬升处切入、保留完整自然收尾 → 成片 **2:47.6**，正好落在 2-3 分钟。这是"重新剪"时处理长前奏的通用判断依据。
- 片段从 24 段扩到 **30 段**填满更长的曲长（平均 5.6s/段），同一素材用不同 in-point 挖第二段以补足数量。
- 输出 `漂亮的恶意_校园MV_2.mp4`（1280x720@24, H.264 High yuv420p bt709, AAC 48kHz 193k, 68MB）。
- 脚本 `video/mv_build_v2.py`：结构比 v1 更稳——逐片段渲染到 **ASCII 路径**工作目录（`%TEMP%\mv_v2`），再用 **concat demuxer** 拼接（完全不用巨型 filter_complex），章节转场仍是白场 dip（在片段内部 fade in/out），最后 `-i list.txt -i bgm -shortest` 混音频 + loudnorm -14LUFS。
- 新增经验：
  - **Windows 版 ffmpeg 不认 MSYS 的 `/tmp` 路径**（bash 里 $TMP 能 ls 到，但 exe 打不开），跨 bash/Python 传路径必须用真实 Windows 路径或项目内路径；
  - concat demuxer 是长片拼接的最稳方案，比 filter_complex concat / xfade 都可靠，前提是各段编码参数（fps/pix_fmt/timebase）统一，用 `-video_track_timescale 24000` 对齐；
  - 分镜表要加 in-point 越界**自动钳制**（素材仅 15s，`in+dur<=14.9`），比断言失败更省事；
  - xstack 在本机 ffmpeg 7.1 上静默失败，检查帧拼图改用 `hstack`+`vstack`（或直接 Read 单帧）。
  - 本机 Python 环境会被重置：`imageio_ffmpeg` 曾丢失，需 `pip install imageio-ffmpeg` 重新取回 ffmpeg 二进制。
