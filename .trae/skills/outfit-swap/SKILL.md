# 人物换装（凡人资源包 · 65535 图生图）

一句话流程：用户说「{角色}换上{服装}」→ 检索角色三视图（基础）与服装道具 → 取服装文字描述 → 造型确认 → 调 65535 技能图生图 → 核验交付 → 归档新形象。

## 触发条件

用户提到给本地资源包中的某个人物换装/换衣服/穿上某件服装，典型句式：

- 「穆沛灵换上比基尼-2」
- 「给韩立换上宫装-3」
- 「南宫婉换一身比基尼」

## 固定约定

| 项 | 值 |
|---|---|
| 生成通道 | **65535 技能**（图生图：参考图=角色三视图，新服装以文字描述锁定） |
| 资源包根目录 | `assets\`（当前有 `凡人` 资源包） |
| 角色目录 | `assets\凡人\character\{角色名}\` |
| 角色三视图（基础） | `assets\凡人\character\{角色名}\人物三视图（基础）.png`（括号为全角） |
| 角色总索引 | `assets\凡人\character\_人物资产索引.md` |
| 服装目录 | `assets\凡人\props\服装\{服装名}\`（目录名是 `props`，不是 `propss`） |
| 服装命名约定 | `{服装名}-{编号}.png`，编号从 1 起；部分文件名带多余空格（如 `宫装-2 .png`），匹配时忽略 |
| 服装文字索引 | `assets\凡人\props\服装\_服装资产索引.md`（服装描述登记处，本流程依赖） |

## 执行流程

### Step 1 — 解析指令

从消息中解析出**角色名**和**服装名（含编号）**：

「穆沛灵换上比基尼-2」→ 角色=穆沛灵，服装=比基尼-2

- 服装名不带编号 → 列出该服装目录下全部编号让用户选择
- 只有角色没有服装 → 询问想换什么服装

### Step 2 — 定位角色（带容错）

1. 在 `assets\凡人\character\` 下查找与角色名同名的文件夹
2. 未命中 → 读 `_人物资产索引.md` 做名字容错匹配（常见形近/同音字：**穆 ↔ 幕**，如「穆沛灵」→`幕沛灵`）；也可跨 `assets\` 下其他资源包的 character 目录搜索
3. 仍未命中 → 列出可用角色名单让用户选择，不要臆测

### Step 3 — 取角色三视图（基础）

按以下顺序匹配（元瑶的「基础」文件名是 `人物人视图（基础）.png`，属已知笔误，须兜底）：

1. `人物三视图（基础）.png`
2. `人物人视图（基础）.png`
3. 该角色目录下文件名含「基础」的任意 png

角色没有「基础」形象时（如 跟班A、跟班B、马姓老者），列出该角色现有形象让用户选择后再继续。

### Step 4 — 取服装文字描述（65535 方案关键）

65535 图生图通过**文字描述**锁定新服装（参考图只传角色三视图），而 agent 无法查看道具图内容：

1. 读 `assets\凡人\props\服装\_服装资产索引.md`，查该服装是否已登记文字描述
2. 已登记 → 直接使用，进入 Step 5
3. 未登记 → 请用户用一两句话描述该道具图（款式、配色、材质、标志性细节），并**当场登记**进索引供以后复用
4. 服装目录/编号不存在 → 列出现有服装或编号让用户选

### Step 5 — 造型确认（65535 技能强制流程）

按 65535 技能「三视图生成前确认」向用户展示并确认，得到明确同意后才提交：

1. **修改点**：表格呈现（角色 / 造型设计=服装文字描述 / 参考图来源=基础三视图）
2. **画风**：默认以基础三视图为画风与制图规范基准，仅更换服装；排版默认**沿用参考图原版式**（用户要两列版式则改用 65535 固定排版提示词）；更换画风必须单独确认
3. 用户明确说「不用确认直接生成」→ 跳过确认

### Step 6 — 调用 65535 生成

遵循 65535 技能全部规则（模型选择、JSON 构造、提交、轮询、下载），本技能的参数约定：

- 模型：默认 `gpt-image-2`（用户指定其他模型时原样传入）
- `input.image`：角色三视图（基础）转为 base64 data URI（身份与画风基准）
- `input.prompt` 拼接顺序（默认沿用参考图原版式时）：
  1. 排版约束：完整角色设定稿，白色背景，沿用参考图的版式与构图（三视图并排、全身站姿）；**画面中不出现任何文字、字母、数字、标注或水印**
  2. 身份锁定：保持参考图人物的面部特征、发型、瞳色、体型与三视图构图完全一致，仅更换全身服装
  3. 新服装描述（Step 4 的文字描述）
- `size`：`16:9`，`resolution`：`2k`，`n`：`1`
- 提交后每 2 秒轮询；成功后下载到当前项目 `generated-images\`

### Step 7 — 交付与核验

- 结果图用 computer:// 链接交付，并报告任务 ID
- 请用户肉眼核验三点：服装已更换、脸部发型体型未变、**画面无文字/标注**
- 不满意 → 调整服装描述或强调无文字约束，重新确认后重试（不重复创建替代任务）

### Step 8 — 归档（用户满意后）

- 复制为 `assets\凡人\character\{角色}\人物三视图（{形象名}）.png`（形象名默认=服装名-编号，如「比基尼-1」）
- `_人物资产索引.md` 对应角色下补一行形象记录
- 服装索引中该服装描述仍是占位时，借用户确认的机会补全

## 特殊情况

| 情况 | 处理 |
|---|---|
| 请求的服装恰好是角色已有形象（如「幕沛灵换上校服」） | 直接交付现成的 `人物三视图（校服）.png` 并说明，不花钱；用户明确要重新生成时才走流程 |
| 服装索引无描述且用户未提供 | 必须先取得描述，不得臆测道具图内容 |
| 65535 API Key 未配置 | 按 65535 技能配置流程引导用户 |
| 生成画面出现文字/标注 | 在提示词末尾再次强调"不出现任何文字"后重试 |
| 任务失败 | 按 65535 技能失败规则报告 error_code 与 error_message，不盲目重试 |

## 历史经验

- 2026-09-16 前：本技能曾用 RunningHub 换装应用（appId `2012848202482978818`，模特图+替换衣物图双图输入），实测存在「部分服装参考图不被采用、输出仅重绘原图」问题（柳眉×宫装-2 连续两次未生效、柳眉×比基尼-1 成功），且无法稳定核验，故全面改用 65535 文字描述方案。该应用仍登记于 `assets\应用注册表.md`，仅供手动使用。

## 完整示例

用户：「柳眉换上比基尼-1」

1. 解析 → 角色=柳眉，服装=比基尼-1
2. 角色图 → `assets\凡人\character\柳眉\人物三视图（基础）.png`
3. 服装描述 → 查 `_服装资产索引.md`（无则请用户描述并登记）
4. 造型确认表 → 用户同意
5. 65535 图生图（参考图=基础三视图；prompt=排版约束+身份锁定+服装描述）→ 下载到 `generated-images\`
6. 交付核验 → 满意后归档为 `人物三视图（比基尼-1）.png` 并更新人物索引
