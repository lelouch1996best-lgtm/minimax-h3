# 宫装女友热点播报（韩老魔的宫装女友）

一句话流程：trends-hub 抓 B站+抖音热点 → 选适合"女友跟男友唠"的话题（无合适则自创有趣脚本）→ story-craft 写第一人称男友 POV 剧本 → 按剧本场景从凡人资源包选女性角色三视图，65535 图生图生成"人物+场景"一体的真人质感参考图 → 交 h3-drama-producer 出片（t8balance、9:16、mp0.86 默认，BGM 一律后置）→ Step 5B 合成与统一 BGM → sau 发布（默认 B 站 + 抖音双平台）。

## 触发条件

用户想做"女友跟你说热点时事"类短视频：说「来一期宫装女友说热点」「抓个热点做女友视频」「女友播报今日热点」「韩老魔的宫装女友更新一期」等，或要求自动化执行"热点 → 女友 POV 剧本 → H3 视频"整条链路时。已有成片时说「发布/同步到 B站/抖音」「双平台发一下」，直接走 Step 7；只要求为已有合成视频选/生成/复用 BGM，直接走 Step 5B。

## Step 1 — 抓取热点（trends-hub MCP）

按 MCP 三步协议调用（先 LS 服务器工具目录 → Read 工具 JSON 描述 → run_mcp），服务器名 `mcp_trends-hub`：

| 工具 | 参数 | 说明 |
|---|---|---|
| `get-bilibili-rank` | `{"type": 0}` | B 站全站排行（可换分区：1 动画 / 3 音乐 / 4 游戏 / 5 娱乐 / 160 生活 / 181 影视） |
| `get-douyin-trending` | `{}` | 抖音热搜榜 |

- 两榜并行拉取，合并去重，保留排名与热度值
- 整理 Top 15—20 条热点列表（标题 + 来源 + 热度），作为 Step 2 选题池
- 服务器整体不可用（未接入/未启用）时见「特殊情况」

## Step 2 — 选题（女友唠嗑适配评估）

**评估四维**：情绪可发挥度（能否撒娇/调皮/吃醋地聊）、情侣日常感（真的会跟男友分享吗）、画面可呈现度（单场景 15 秒内可演）、话题安全性。

**排除（不进候选）**：政治敏感、灾难事故伤亡、暴力犯罪、涉未成年人负面、严重社会对立、色情低俗。

**偏好类型与情绪匹配**：

| 话题类型 | 推荐情绪 |
|---|---|
| 游戏上线 / 游戏圈 | 兴奋安利、小得瑟 |
| 影视综 / 明星八卦 | 吃瓜、调皮 |
| 科技数码新品 | 好奇、兴奋 |
| 萌宠趣事 | 心疼、软萌撒娇 |
| 美食 | 撒娇求投喂 |
| 文化国风 | 小得瑟科普、傲娇 |
| 体育趣闻 | 激动、调皮 |
| 网络热梗 | 调皮玩梗、傲娇考你 |

- 选出 Top 3—5 候选，附推荐情绪与切入角度，展示给用户（标注推荐项）；用户无偏好时（含无人值守）直接采用推荐项并说明理由
- **两榜均无合适话题（全被排除或情绪无从发挥）→ 自创有趣脚本**，不硬蹭。自创方向示例：修仙界热搜体（"灵界热搜第一：某韩姓老魔又双叒闭关了"）、宫装女友现代初体验系列（第一次点外卖 / 第一次刷短视频）、古风语言聊现代事的反差萌。须向用户说明"今日热点不适配，改为自创"

## Step 3 — 剧本（story-craft）

调用 `story-craft` 技能（Skill 工具，插件全名 `trae-remote-official:story-craft:story-craft`）创作，传入以下定制约束（沿用其人物灵魂设定与反 AI 味文笔体系）：

- **体裁**：甜宠日常短剧本，喜剧向，风格温度 2—3 档
- **视角**：全程第一人称男友 POV，女友单人对着镜头说话；男友不出镜，至多背景里"嗯"一声
- **人物**：宫装女友一名（角色由 Step 4 定），按凡人 IP 人物性格做角色卡
- **对白**：中文口语、软糯甜妹感，单集 3—5 句（15 秒内自然说完）；热点信息像唠嗑一样自然带出，**禁止新闻播报腔**
- **情绪**：按 Step 2 匹配结果（撒娇 / 调皮 / 吃醋 / 好奇 / 兴奋安利 / 小得瑟 / 心疼 / 吃瓜 / 傲娇，可组合）
- **场景**：暖光室内（闺房 / 卧室 / 书房），与宫装造型协调，单场景不转场
- **结构**：起（引入热点）→ 承（情绪展开）→ 收（撒娇收束或抛钩子）；单片时长 10—15 秒按节奏定（对白按约 4—5 字/秒估算容量，15s 约 60—70 字）；超过 15s 容量按固定约定「编号硬规矩」拆片

流程约定：

1. 扫描 `<项目>\` 下已有 `E??-*` 分集目录确定本集编号：无则 E01，否则取最大基号 +1（`E{NN}A`/`E{NN}B` 段目录按基号 E{NN} 计入；曾被订正释放的空号如 E09 可回填复用，回填须在总纲注明）
2. 编号确定后立即建目录（含六子目录）：预判单片建 `E{NN}-{选题关键词}\`，完整剧本落 `剧本\E{NN}-{选题关键词}-剧本.md`；预判拆片建 `E{NN}A-{选题关键词}上\` 与 `E{NN}B-{选题关键词}下\` 两个段目录，**完整剧本一份只落 A 段** `剧本\E{NN}-{选题关键词}-剧本.md`（B 段 `剧本\` 留空或放分段对白卡）
3. **剧本确认门**：用户在场时，剧本展示确认故事走向与情绪后再进 Step 4；**goal / 无人值守模式**不等待确认，直接落盘继续，台账注明「剧本未经用户确认（无人值守）」
4. 拆片段产物命名一律带段后缀：`提示词\E{NN}A.md` / `E{NN}B.md`、`images\E{NN}A_{角色}_{场景}.png`、`video\宫装女友E{NN}A_*.mp4`、`任务记录\t8balance-E{NN}A-*.json`（E08 段内实际为基号/E09 旧名，属订正前历史遗留，新集按本条执行）

## Step 4 — 场景参考图（按剧本定制，真人质感图生图）

**核心原则：参考图必须与本集剧本场景一致。** 不再随机取图——先解析剧本里的场景，再从凡人资源包任选一名女性角色的三视图，用 65535 图生图把"该角色 + 该场景"合成一张真人质感图片，作为 t8balance 唯一主参考图（node 6）。角色、场景、服化道在图里一次锁定，Step 5 提示词只负责动态与对白，避免"图里是书房、剧本里是灯会"的错配。图内画质统一按 `references/realism-baseline.md` 的现实感基准渲染：**生活照 / 手机随手拍观感、反 CG、反美颜**，不做影棚大片。

### 4.1 解析剧本场景

从 Step 3 已确认的剧本中提取并向用户简报（示例取自实际归档 E10）：

| 要素 | 例子（E10 快舟火箭） |
|---|---|
| 地点 / 空间 | 闺房夜窗边、夜晚 |
| 关键陈设 / 道具 | 手中手机屏上的火箭尾焰光迹、窗外弯月 |
| 光线 / 氛围 | 屏光映面、夜色柔和 |
| 机位 / 构图 | 男友视角平视近景，人物居中偏近景，9:16 |
| 情绪 / 动作 | 兴奋举机安利、看男友反应、撒娇求带现场 |

场景必须是**单场景**（与剧本"单场景不转场"一致）；剧本写了多个场景时取主场景，其余写进 Step 5 提示词即可。

### 4.2 选角色与造型

- 从固定约定的女性角色池中**任选 1 名**（宫装造型优先，因为本系列是"宫装女友"；非宫装古风造型可在场景明显不适配宫装时选用）
- 气质与场景情绪匹配：温婉场景（书房/茶事/灯会）→ 南宫婉、李缨宁、梅凝、文思月；活泼场景（安利/玩梗/看热闹）→ 凌玉灵、墨彩环、元瑶、燕如嫣；高冷/美艳 → 幕沛灵、紫灵、穆兰圣女、柳眉；其余（宋玉、辛如音、银月）按场景气质就近选用
- **避开上一集角色**（查总纲台账），保证系列轮换；用户本次直接点名角色时以用户为准（可点名池外角色，如 E05 文思月）
- 定位三视图文件：`d:\work\minimax_h3\assets\凡人\character\{角色}\人物三视图（{造型}）.png`
  - 目录名容错：用户常把"幕沛灵"写成"穆沛灵"（穆=幕），以实际目录为准（资产库目录名为「幕沛灵」）
  - 个别非标准命名：元瑶基础为 `人物人视图（基础）.png`、李缨宁另有 `人类质感.jpg`；拿不准先 LS 该角色目录
  - 优先选与目标画风接近的造型（宫装/基础古风）；**昭和造型可选**，但只接受真人/古风质感的昭和，**不要选"昭和·漫画风""校服"等带明显漫画或二次元底子的造型当底图**，拿不准先 Read 该造型三视图确认画风
- 从 `_人物资产索引.md` 复制该角色外观描述（五官/发型/服装锚点），供提示词身份锁定使用；索引标"以图片为准"且环境无多模态读图能力（Read 图片报错）时，身份锁定段改用**引用式写法**——「严格保持参考图中同一女性的面部五官、脸型、发型发饰与服装形制不变（以参考图为唯一身份基准，不换人、不改发型与服装形制）」，不罗列具体特征（E05 文思月验证：出片身份稳定）

### 4.3 65535 图生图生成（真人质感 = 现实感基准模板）

调用 `65535` 技能的图生图任务（接口细节以该技能 SKILL.md 为准）：

- `input.image`：三视图 PNG 转 base64 data URI（本地文件直接编码，无需先上传）
- `input.prompt` 中文撰写，**拼装顺序：构图排版 → 身份锁定 → 真人质感 → 剧本场景 → 反向约束**
- 真人质感段与反向约束段按 `references/realism-baseline.md` 的**现实感基准**撰写（生活照 / 手机随手拍 / 反 CG / 反美颜），是全系列固定模板，只替换场景与动作两处；场景段不写"背景虚化"，与基准"不过度虚化背景"保持一致

```

生活照式的自然取景：允许轻微倾斜、留白不均、不完全居中的构图，但人物始终是画面主体、面部完整清晰。
画面只保留一个人物，三视图排版仅作身份参考，不要出现拼贴/多视图/白背景。
```

### 5B.4 混音合成

系统 PATH 的 ffmpeg 为精简版（缺 aac 编码器），取完整版：`python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"`

```powershell

  -filter_complex "[1:a]volume=0.25[bgm];[0:a][bgm]amix=inputs=2:duration=first:dropout_transition=0[a]" `
  -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k `
  "<输出>E{NN}.mp4"
```

- **产出统一命名 `E{NN}.mp4`**（发布版惯例，沿用 E01）：拆片集落合集目录 `E{NN}-{关键词}合集\video\`，单片落本集 `video\`。E08 实际产物名为 `宫装女友E08_秋日火锅合集.mp4`，属订正期历史例外不回改，新集一律 `E{NN}.mp4`
- BGM 音量 0.2—0.3（人声与环境音为主、BGM 垫底）；`duration=first` 保证输出不超视频时长
- 新生成的 BGM 已带淡入淡出（`--trim`）；复用曲库且时长超出视频时先 `--trim` 重截或滤镜补 `afade`

- **Step 7 发布一律用混音版 `E{NN}.mp4`**（走过本步的集）

- **短信验证码风控门**（连续发布、新设备时高概率触发，与模式无关）——**硬性交互暂停门**：
  1. 日志出现「📱 检测到短信验证码弹窗」「已点击"获取验证码"」后，**立即停止当前回合的所有后续工具调用**（不读盘、不轮询、不重试、不进 7.3/7.4），直接把「请查看手机短信，把 6 位验证码发我」作为本回合终点输出给用户，然后**保持等待**
  2. **goal / 无人值守模式必须显式挂起**：先调用 `update_goal(status="blocked")` 把目标置为 blocked（说明正在等待用户提供抖音 6 位验证码），再结束回合；绝不让自动续跑在没拿到验证码前接着往下走
  3. 用户在后续回合给出验证码后，**必须无 BOM 写入**：`[System.IO.File]::WriteAllText('D:\work\social-auto-upload\verify_code.txt', '<验证码>')`（PowerShell `Set-Content -Encoding UTF8` 会写 BOM，验证码变 `﻿123456` 必然失败；上传器读取后自动删文件），写完后继续/恢复发布流程
  4. 程序自动填入并点「验证」，日志出现「🥳 视频发布成功」即可；同一验证码被污染重试消费后会失效，别反复提交

  - `GET https://creator.douyin.com/web/api/media/aweme/post/?aid=2906&count=10&cursor=0&type=1&publish_time_type=0&need_charge_info=false`（type=1 已发布；type=2 草稿/审核中）

### 7.3 抖音话题 5 个硬上限（重点防坑）

- 每条作品**最多 5 个话题实体**。传 6 个以上时，前 5 个正常变蓝，第 6 个起编辑器不再转换，且话题联想弹层/IME 会把后续中文打成乱码（如 `#AI视频 #宫装女友…` 变 `#A#I#宫#搞#沙修仙同人…`），这是平台限制不是输入抖动，加重试/放慢打字都无效
- 选话题优先级：热点话题 1 个（流量）+ 剧名 1 个（系列沉淀）+ IP 名 1—2 个（凡人修仙传/角色名）+ 品类泛标签 1 个（AI短剧/AI视频），共 5 个
- 已发布作品若话题已乱码：可走作品编辑页修复（`https://creator.douyin.com/creator-micro/content/post/video?mid={aweme_id}&enter_from=edit_item`，从内容管理点「编辑作品」是同标签页跳转），用 patchright 清空 contenteditable（`div.zone-container[contenteditable="true"]`）后 **`keyboard.insert_text()` 粘贴整段（绕过 IME）**，只保留 5 话题，点「提交修改」，等「修改成功」toast，再回读 API 确认。老的 `/web/api/media/aweme/modify/` 接口已失效（返回 "Url doesn't match"），只能 UI 改
