# 真人质感风格转换（65535 图生图 · 一步生成）

一句话流程：用户说「把{角色}{形象}转成真人质感」→ 检索角色形象 → 选场景 → 65535 生成「人物+场景」真人质感图 → 核验交付 → 归档。

## 触发条件

用户提到将本地资源包中的3D国漫风/二次元人物转为真人/写实/真人质感风格，典型句式：

- 「把李缨宁红色宫装转成真人质感」
- 「南宫婉基础版真人化」
- 「给韩立来个真人版」
- 「把紫灵宫装转写实风格」
- 用户上传一张图并说「转真人」「真人化」

## 固定约定

| 项 | 值 |
|---|---|
| **生成通道** | **65535 图生图**（gpt-image-2，被审核拒则切 gemini-3-pro-image） |
| 资源包根目录 | `assets\`（当前有 `凡人` 资源包） |
| 角色目录 | `assets\凡人\character\{角色名}\` |
| 角色总索引 | `assets\凡人\character\_人物资产索引.md` |
| 输出目录 | 当前项目 `generated-images\` |
| 归档命名 | `人物（真人质感-{形象名}-{场景}）.png` |

## 场景库（随机选一个，用户也可指定）

室内：卧室、书房、客厅、厨房、浴室、衣帽间、咖啡馆、书店、办公室、火车车厢、地铁、电梯
室外：街道、公园、花园、海边、山顶、古镇巷子、樱花树下、雨夜街头、天台、游泳池

## 执行流程

### Step 1 — 解析指令

从消息中解析出**角色名**、**形象名**（可选，默认「基础」）、**场景**（可选，随机选）、**画幅比例**（可选，默认 9:16 竖图）：

「把李缨宁红色宫装转成真人质感」→ 角色=李缨宁，形象=红色宫装，场景=随机，比例=9:16

- 用户上传了图片 → 使用用户上传的图作为参考，跳过 Step 2
- 只有角色没有形象 → 默认使用「基础」形象
- 角色或形象不明确 → 列出可用选项让用户选择

### Step 2 — 定位角色与形象（带容错）

1. 在 `assets\凡人\character\` 下查找与角色名同名的文件夹
2. 未命中 → 读 `_人物资产索引.md` 做名字容错匹配（常见形近/同音字：**穆 ↔ 幕**）
3. 在角色目录中查找指定形象的三视图 png：
   - 精确匹配 `人物三视图（{形象名}）.png`
   - 模糊匹配：文件名含「{形象名}」的 png
   - 形象名=基础 → 按 `人物三视图（基础）.png` → `人物人视图（基础）.png` → 含「基础」的 png 顺序兜底
4. 仍未命中 → 列出现有形象让用户选择

### Step 3 — 方案确认

向用户展示并确认：

| 项目 | 内容 |
|---|---|
| **角色** | xxx |
| **原形象** | xxx |
| **场景** | xxx（随机选的，不满意可以换） |
| **画幅** | 9:16 竖图 / 16:9 横图 |
| **风格** | 真人摄影质感，一步生成 |

用户确认后开始执行。用户说「不用确认直接生成」→ 跳过。

### Step 4 — 65535 生成真人质感图

使用 65535 图生图，模型优先 `gpt-image-2`（被审核拒则自动切 `gemini-3-pro-image`）。

参数约定：
- `input.image`：角色三视图（或用户上传图）转为 base64 data URI
- `input.prompt` 拼接顺序：
  1. **场景描述**：{场景}的环境描写，细节丰富（如「温馨的中式书房，午后阳光从木格窗洒入，实木书架上摆满线装古籍，深色书桌上放着文房四宝和冒着青烟的铜香炉，地面铺着编织地毯，古雅宁静的氛围」）
  2. **人物身份锁定**：保持参考图人物的面部特征（眼型、鼻型、唇形、脸型轮廓）、发型发色、瞳色、体型完全一致，穿着{服装描述}
  3. **姿态动作**：人物在场景中的自然姿态（如「站在书桌旁，一只手轻轻搭在桌沿，身体微侧，看向镜头，神情优雅从容」）
  4. **真人质感强化**：ultra photorealistic, real human skin texture with visible pores and fine lines, natural skin tone with subtle blush, real hair strands with individual hairs and flyaways, realistic silk and sheer fabric textures with natural folds and drapery, cinematic natural lighting with soft shadows, shallow depth of field, professional portrait photography, shot on Sony A7R IV with 85mm f/1.4 lens, 8K ultra high detail, real person photo quality
  5. **画幅**：`size` = `9:16`（默认）或 `16:9`，`resolution` = `2k`，`n` = `1`
- 提交后每 2 秒轮询；成功后下载到 `generated-images\`
- 如果 gpt-image-2 被安全审核拒绝 → 自动切换 `gemini-3-pro-image` 重试，并告知用户

### Step 5 — 交付与核验

- 结果图用 computer:// 链接交付
- 请用户核验：
  1. 人物身份一致（脸、发型、服装对得上）
  2. 场景自然合理
  3. 真人质感到位
- 不满意 → 调整方向：
  - 身份走样 → 加强 prompt 中的身份锁定描述重试
  - 真人感不够 → 加强真人质感描述重试
  - 场景不好看 → 换个场景重新生成
  - 姿势不对 → 调整姿态描述重试

### Step 6 — 归档（用户满意后，仅资源包角色图）

- 复制最终图为 `assets\凡人\character\{角色}\人物（真人质感-{形象名}-{场景}）.png`
- `_人物资产索引.md` 对应角色下补一行形象记录
- 用户上传的外部图片不需要归档

## 特殊情况

| 情况 | 处理 |
|---|---|
| 角色已有同款真人质感形象 | 直接交付现成图片并说明；用户明确要重新生成时才走流程 |
| 65535 API Key 未配置 | 按 65535 技能配置流程引导用户 |
| gpt-image-2 被审核拒 | 自动切换 gemini-3-pro-image 重试 |
| 生成后人物身份走样 | 加强面部特征锁定描述后重试 |
| 任务失败 | 报告 error_code 与 error_message，不盲目重试 |

## 完整示例

用户：「把南宫婉宫装转成真人质感」

1. 解析 → 角色=南宫婉，形象=宫装，场景=随机（选了「书房」），比例=9:16
2. 角色图 → `assets\凡人\character\南宫婉\人物三视图（宫装）.png`
3. 方案确认 → 用户同意
4. 65535 图生图（参考=宫装三视图；prompt=书房场景+身份锁定+姿态+真人质感强化）→ 下载到 `generated-images\`
5. 交付核验 → 满意后归档为 `人物（真人质感-宫装-书房）.png`
