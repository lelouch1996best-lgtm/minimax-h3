# 韩老魔歌舞团·舞蹈复刻（李缨宁们在宫殿里跳舞）

一句话流程：解析用户指令（角色 + 造型 + 场景 + 舞蹈）→ 扫 `dances\` 目录选/定舞蹈源视频 → 定位角色三视图 → 65535 图生图生成「角色 + 宫殿场景 + 舞蹈动作」一体、真人质感的**全身**参考图 → 用 `runninghub_app.py` 调应用 `1975951975441412098` 做舞蹈动作迁移（参考图给人物外观、舞蹈视频给动作）→（可选）铺 BGM → sau 发布（默认 B 站 + 抖音双平台）。

## 触发条件

用户做「让凡人角色跳指定舞蹈」类短视频：说「用李缨宁宫装在一个大殿复刻 dances 里的那个舞」「来一期舞蹈复刻」「把这个舞换成 XX 角色跳」「做舞蹈动作迁移视频」等；已有成片时说「发布/同步到 B站/抖音」，直接走 Step 5。

## Step 1 — 解析指令与选舞蹈

从用户指令中提取五要素，缺失项及时补齐（用户点名之外用【推荐】值）：

| 要素 | 示例（李缨宁·大殿） | 缺失时的默认 |
|---|---|---|
| 角色 | 李缨宁 | 从瑞士池任选，避开上一条成片角色 |
| 造型 | 宫装 | 宫装优先（本系列「歌舞团」以宫装敦煌为主） |
| 场景 | 大殿（宫殿） | 宫殿大殿 / 舞台 / 庭院，单场景 |
| 舞蹈 | dances 目录中的某支 | 列目录让用户挑，不擅自定 |
| 平台 | B 站 + 抖音 | 双平台 |

- **选舞蹈**：LS `<项目>dances\` 列出可用舞蹈视频（文件名 + 格式），展示给用户选择；用户指令已指定文件名/关键词则直接定位。空目录或列不出 → 停下来请用户放入舞蹈视频，**不臆造源视频**
- 选舞蹈后可播发器前端展示不了视频，用文件名与时长代说明，说明该舞将作为「动作源」，人物外观由参考图决定

## Step 2 — 选角色与造型

- 从 `assets\凡人\character\` 角色池任选（宫装造型优先：凌玉灵、南宫婉、幕沛灵/红宫装、李缨宁/宫装·红色宫装、穆兰圣女、紫灵、文思月；敦煌/古风造型按舞蹈气质选用），避开上一条成片角色，保证轮换
- 定位三视图 `人物三视图（{造型}）.png`；李缨宁另有 `红色宫装`、`人类质感.jpg`（真实肤质参考）等造型，按需选
- 从 `_人物资产索引.md` 复制该角色外观描述（五官/发型/服装锚点）供身份锁定；索引标「以图片为准」且无多模态读图能力时，身份锁定改用**引用式写法**——「严格保持参考图中同一女性的面部五官、脸型、发型发饰与服装形制不变（以参考图为唯一身份基准，不换人、不改发型与服装形制）」
- **避免**带明显漫画/二次元底子的造型当底图（昭和·漫画风、校服等），优先真人/古风质感造型

## Step 3 — 生成全身舞蹈参考图（65535 图生图，真人质感）

调用 `65535` 技能（Skill 工具）的图生图任务：`POST https://task-api-1-cn.65535.space/v1/tasks`，`kind=image`、`model=gpt-image-2`、`size=9:16`、`resolution=2k`、`n=1`；`input.image` = 三视图 PNG 的 base64 data URI；`input.prompt` **拼装顺序：构图排版（全身）→ 身份锁定 → 真人质感 → 剧本场景 → 反向约束**。需环境变量 `S65535_API_KEY`（缺失报用户配置，不硬编码 key）。

真人质感段与反向约束段按 `references/realism-baseline.md` 现实感基准照抄；与宫装女友近景照不同，本技能构图段必须落到**全身**：

```
画面只保留一个人物，三视图排版仅作身份参考，不要出现拼贴/多视图/白背景。

背景不刻意虚化、环境细节清晰可辨。

手与手指的数量、关节、长度、交叠与握持合理（无多指、无粘连）；
**全身完整：不裁切头部、不裁切脚部、不出现半身或只有上半身的构图**；
```

- 轮询 `GET /v1/tasks/{id}`（约每 2s）至 `done`，失败读 `error_code/error_message` 处理；下载 `result_urls` 到 `<项目>generated-images\`（交付/复用）并复制到本任务 `参考图\`
- **成片前核验四要素**（图比视频便宜，先在图阶段把关）：① 身份与三视图一致（没换人）② 真人质感照片而非 3D/CG/美颜 ③ **全身完整、脚部未裁切** ④ 场景与指令一致、无文字水印多视图拼贴。任一不合格针对该项改 prompt 重生成；连续 2 次失败按「特殊情况」兜底。用户已说「直接生成/不用确认」或无人值守时，跳过展示直接归档，出片后按需抽帧核验身份锚点
- 该图即 Step 4 的参考图（`--file "299:image=..."`），兼作发布封面；归档 `参考图\D{NN}_{角色}_{场景}.png`，登记资产清单

## Step 4 — 舞蹈动作迁移（runninghub 应用 1975951975441412098）

调用 `runninghub` 技能（Skill 工具）的 AI 应用流程，脚本 `<本技能目录>\scripts\runninghub_app.py` 实为 `d:\work\minimax_h3\.trae\skills\runninghub\scripts\runninghub_app.py`。**先 `--info` 查线上节点当前值，再 `--run` 提交**（节点定义以线上为准，勿凭记忆）：

```powershell
python "d:\work\minimax_h3\.trae\skills\runninghub\scripts\runninghub_app.py" --info 1975951975441412098
```

关键节点（2026-09-19 实测线上值；每次运行前仍以 `--info` 为准）：

```powershell
  -o "d:\work\minimax_h3\韩老魔的歌舞团\D{NN}-{角色}-{舞名}\video\D{NN}_舞蹈迁移.mp4"
```

- **参考图/视频上传后勿立即提交**：openapi 文件写入 RunningHub 工作区有分钟级同步延迟，秒提交会「文件不存在」零扣费失败，间隔几分钟重提同一 payload 即可
- 成片核验：抽 2—4 帧看 ① 身份锚点没换人 ② 动作与源舞蹈一致 ③ 全身/无文字水印 ④ 无肢体畸变（多指、粘连、飘浮）。问题轻则调 `姿势强度/姿势选择` 重跑，重则回 Step 3 重生成参考图（全身构图不足时）
- 加载帧上限 840 帧：源舞超 28 秒时，先决定截段——通过 `499 跳过帧` 与 `422 帧上限` 搭配截取段落，或用 ffmpeg 先把源视频截到目标时长再传
- 产出的 task 回执（payload/result）落 `任务记录\`；RunningHub 返回 URL 为内部地址，**必须下载到本地再交付**，不发裸 URL
