# 发布文案与起名（多平台）

为待发布内容创作**标题 / 简介 / 标签 / 话题**。本技能是**唯一负责创作文案**的环节；发布脚本只解析文案、不生成创意。

## 🔴 标题总纲：20 字以内 + 必须带爆点（2026-10-11 用户指定）

**所有平台标题一律以 20 个汉字为上限来写**（比各平台硬限制更严——20 字是全平台通用安全线，抖音/快手/小红书显示更友好，B 站也在其内；B 站如需带剧名+集号后缀，主体部分仍须 ≤20 字）。**超过 20 字一律砍到 20 字以内，宁短勿长。**

**每条标题必须有一个"爆点"——让人 1 秒内手比脑子快地点进来。** 满足以下**可检验标准**才算合格：

| 检验项 | 要求 |
|---|---|
| **引爆词** | 标题里至少 1 个"强刺激词"（可感知的名词/动词/数字，见「引爆词库」）。去掉所有辅助词后，剩下的骨架词**单独拿出来就想点** |
| **钩子单一** | 一句话只留**一个**钩子，不堆信息；钩子要具体（动作/物件/数字/反差），不要抽象（"很精彩""值得看"） |
| **未闭合** | 信息**故意不说完**——结果、答案、身份、原因至少留一个悬着，逼观众看完/点开 |
| **口语化** | 像跟朋友说话，不用书面词、不用晦涩词（短视频文案晦涩=直接被划走） |
| **不剧透** | 遵守「标题风格禁区」（禁数量+关系噱头、禁结局反转剧透）——爆点靠**悬念**制造，不靠**结论** |

**一句话公式**：`爆款标题 = 直击人性（好奇/反差/共情/避害） + 吸睛词汇（引爆词） + 顺口句式`

**黄金 3 秒法则的标题版**：标题就是"屏幕前的 3 秒"。观众只给你 1 秒——**前 6 个字必须已经抛出一个让人停下的东西**（疑问、反差、数字或强动作），不许用"大家好""今天聊聊"这种无意义开头。

**两种用法**（同一套规范，产物不同）：

| 用法 | 场景 | 产物 |
|---|---|---|
| **A 完整文案包** | 项目级发布（宫装女友、歌舞团、其他项目），走 `publish_episode.py` 发布 | 落盘《XX-双平台发布文案.txt》 |
| **B 即时起名** | 临时发单条视频、只想问"起个什么标题"、无文案包 | 直接在对话里给出标题/标签，或按需落盘轻量文案文件 |

**用法 B 是本技能面向所有发布场景的通用入口**：用户只说"帮我给这条视频起个标题"时，就用 B——不必走文案包那套格式。但平台规范、标题禁区**与 A 完全一致**，绝不因为"临时发"就放松。

## 三条硬要求（用户 2026-09-22 指定）

1. **合规**：标题、简介、标签/话题严格符合各平台规范（字数、数量、格式，见下表），超长必截断或重写。
2. **精简**：标题一句话留一个钩子，不堆信息、不写满上限；B 站标题可带剧名+集号，抖音标题纯口语钩子。**禁止直白点破设定的噱头词与剧情结论词**——不写「两个女友」「争宠」「争风吃醋」「最后却…」这类数量+关系噱头和结局剧透（2026-09-30 用户指定，详见下方「标题风格禁区」）；用具体动作/物件/悬念做钩子，看点留给正片。
3. **精准**：标签和话题少而准，不凑数。**蹭热点时该热点原文必须原样作为话题**（抖音第 1 个话题＝热点标题原文，一字不改/不缩写/不换近义词），否则拿不到该热点流量；无热点则第 1 个话题取本条内容的核心主题。

## 平台规范

> **标题一律按 ≤20 字写**（总纲硬要求）；下表"平台上限"是各平台的技术截断线，**不是写作目标**——写作永远向 20 字收，向平台上限收是错的。

| | B站 | 抖音 | 快手 | 小红书 |
|---|---|---|---|---|
| 标题 | 主体 ≤20 字 + 剧名集号后缀（总 ≤80）；后缀不计入钩子字数 | ≤20 字（平台截 30）；口语钩子，不带剧名编号 | ≤20 字；口语钩子 | ≤20 字（平台截 20，最严）；可带 emoji |
| 简介/正文 | 可分段，剧情梗概 + 版权/二创说明 | 一自然段，口语化，前两句抓人 | 一自然段，口语化 | 正文 ≤1000 字，首行可重复标题；话题写正文里 |
| 标签/话题 | 标签 **10—12 个**，逗号分隔 | 话题**硬上限 5 个**，编号列表 | 前 3 个有效 | 话题 ≤10 个，写正文 `#xx` |
| 分区 | `--tid 47`（动画·短片/同人） | 无 | 无 | 无 |
| 封面 | 同一张参考图 PNG，不从成片截帧 | 同左 | 同左 | 同左 |
| AI 声明 | 投稿时一次带入（脚本自动） | `--declaration "内容由AI生成"` | 无 | 无 |

> 未列平台（腾讯/百家号/微博等）：标题 ≤20 字、话题 ≤5 个作为保守默认，发布前以该平台最新规则为准。

## 标题风格禁区（2026-09-30 用户指定）

标题只留一个钩子，看点和结论留给正片。以下三类一律不写，双人/多人同框同样适用：

- **数量＋关系噱头**：「两个女友」「两位女友」「两个宫装女友」「双美」「情敌」等
- **直白点破关系/情绪**：「争宠」「争风吃醋」「修罗场」「大型争宠现场」等
- **结局反转剧透**：「最后却…」「没想到最后…」「结尾你绝对猜不到」及把和解/反转结论直接写进标题

正确做法：用具体动作、物件、一句台词感或悬念做钩子。

| | 反面（禁用） | 正面（推荐） |
|---|---|---|
| 抖音 | 两个女友为国庆出游争宠，最后三人一起出发 | 国庆去哪玩？她俩把舆图怼到我面前 |
| B站 | 两个宫装女友为国庆反向出游争宠…｜剧名16 | 国庆反向出游，她俩非要我先点头｜剧名16 |

## 爆款标题公式库（20 字内套用，来源：2026-10-11 联网检索整合）

写标题时**先选公式、再填内容**，比空想快得多。以下 6 个句式实测高频、可套用（按本项目短剧/IP二创场景排序）：

| # | 公式 | 结构 | 示例（短剧向） | 适用 |
|---|---|---|---|---|
| 1 | **反差冲突** | 场景/预期 vs 意外反转 | `我说不要，她直接把门锁了` | 剧情类首选，冲突越强越灵 |
| 2 | **悬念留白** | 话说一半，戛然而止 | `他翻开口袋，掏出的东西我懵了` | 剧情/钩子类，逼观众看完 |
| 3 | **疑问直击** | 抛出让人想知道答案的问题 | `为什么她非要我去见家长？` | 互动引导，评论率高 |
| 4 | **结果前置** | 先甩惊人结果，再留原因 | `三句话，她当场哑火` | 爽点/打脸/反转类 |
| 5 | **身份对号入座** | 用标签让目标人群自动代入 | `当修仙男遇上现代相亲` | IP二创、圈层内容 |
| 6 | **数字冲击** | 具体数字制造好奇 | `一条视频被骂了三千条` | 有可量化数据时 |

**组合用法**：多数爆款标题是**两个公式叠加**，如「反差冲突 + 悬念留白」= `她嫌我土，直到看见我家`。但**钩子仍只有一个**——叠加是让同一个钩子更有力，不是塞第二个卖点。

**制造爆点的 5 个角度**（人性开关，选一个切入）：

- **好奇**：反常识、未完成信息、秘密感（"她不知道的是…"）
- **反差**：身份/处境/前后强对比（越"惨→强"越好）
- **共情**：说出观众想说没说的话、所经历过的处境
- **避害**：踩坑、后悔、警告（"千万别…"）——短剧慎用，易显营销
- **情绪宣泄**：委屈、爽感、得意，把情绪顶到临界

## 引爆词库（标题必须至少含 1 个）

**自检法（权威可复用）**：把标题拆成关键词 → 去掉所有辅助词（的/了/很/就/都…）→ 看剩下的骨架词里**有没有一个单独拿出来就想点的"引爆词"**；没有就强化它。

| 类别 | 引爆词示例 |
|---|---|
| **强动作** | 怼、撕、摔、锁、跪、扛、抢、翻、藏、吞、甩 |
| **强反差** | 没想到、结果、其实、居然、偏偏、当场、一秒 |
| **强悬念** | 直到、下一秒、后来才、原来、真相、秘密 |
| **身份/称谓** | 师尊、圣女、宗主、老公、前女友、老板、亲家 |
| **数字** | 三句、一夜、三千条、第 3 天、99% |
| **情绪词** | 懵了、破防、上头、绷不住、沉默了、傻眼 |
| **高价值** | 白捡、白嫖、稳了、赢麻了、反杀 |

> ⚠️ **引爆词 ≠ 标题党**：词要"强"但必须**与正片内容自洽**。为了冲突反差捏造事实、或把不存在的爆点写进标题，会伤观众预期、被判标题党降流。爆点靠**真实的强瞬间**，不靠**夸大**。

## 起名自检法（拟完逐条过，不过就改）

1. **字数**：≤20 字？超了砍。
2. **引爆词**：骨架词里有没有一个"单独拿出来就想点"的？没有 → 换公式重写。
3. **前 6 字**：开头 6 个字是否已经抛出让人停下的东西（疑问/反差/数字/强动作）？没有 → 重排语序，把最猛的信息挪到最前。
4. **钩子单一**：是否只有一个钩子？塞了第二个卖点 → 删。
5. **未闭合**：结果/答案/身份/原因是否至少留一个悬着？全说完了 → 改回悬念留白。
6. **口语化**：读出来像跟朋友说话吗？有书面词/晦涩词 → 换掉。
7. **不剧透**：对照「标题风格禁区」逐字排查噱头词与结局剧透。


## 热点取词机械规则（不改词）

含空格只去空格；含 `·｜：，` 取分隔符前主段或去符连体；仍不可用取最长完整短语；超约 20 字在词边界截完整前半；被平台拒或无可搜索性时退化为原题核心原词并在文案包「热点」行注明。热点原文须逐字登记在文案包头部「热点」行，且与抖音第 1 个话题字面一致。

## 🔴 封面闸门（发布前必过，2026-10-11 用户指定）

**任何发布动作之前，先在成片同目录找封面——没找到不许静默凑合，必须主动问用户。** 适用用法 A 与用法 B（临时直发同样要过）。

### 第一步：搜索已有封面

在**成片所在目录**、**项目 `images/`**、**项目 `发布/`** 三处按下列优先级找（先命中者胜）：

1. **文案包头部「封面」行指定的路径** → 存在就用（先 `Test-Path` 验证；失效则往下找）
2. **平台专属封面**：`封面_B站` / `封面_抖音` / `封面_快手` / `封面_小红书`（或含平台关键词）——**优先于通用封面**，因为各平台宽高比不同
3. **通用封面**：文件名含「封面」或 `cover`（如 `D03_封面.png`、`_src_cover.jpg`）
4. **文件名以集号开头的主图**（脚本 `resolve_cover()` 的兜底逻辑）

> ⚠️ `publish_episode.py` 的 `resolve_cover()` **会自动挑图当封面**（按文件名排序取第一张），它**不会问、不会生成、找不到就直接报错退出**。所以本闸门是"脚本之外的人工/agent 前置动作"——**别指望脚本替你发现封面缺失**。

### 第二步：找到 → 直接用

把路径写进文案包头部 `- 封面：` 行（用法 A），或直接作为 `--thumbnail` / `--cover` 传参（用法 B）。

### 第三步：没找到 → **主动问用户选哪条路**（不得自行决定）

**禁止**用角色参考图、成片首帧、场景图默默凑一张——**必须把两条路摆给用户选**：

| 选项 | 做法 | 适用 |
|---|---|---|
| **A 用 65535 技能生成封面** | 图生图（65535 `input.image`），**参考图按下述优先级取**；**提示词从简（只给「参考图 + 标题」，见下）**；脚本 `tools\gen_cover_ai.py` | 想要高质量、有设计感的封面 |
| **B agent 自己截帧 + 加简单文字** | 截成片代表帧作主体 → `boxblur` 底 + 居中主体 + `drawtext` 描边标题；模板 `tools\ngw_mpl_make_cover.py` / `tools\make_cover_ep5.py`（**尺寸口径同下节尺寸表：B站 16:10、抖音/快手 9:16、小红书 3:4**） | 要快、要"这就是正片"的直观封面 |

**选项 A 的参考图取图优先级（2026-10-11 用户指定，按序取第一档可用者）**：

1. **本次核验/检查时已截的抽帧 → 直接复用，不要重复截**。常见落点（按成片所在项目实际命名扫一遍，先命中者胜）：
   - `<项目>/核验帧/`、`<项目>/核验/`（如 `一脚踩出的坑爹时刻/核验帧`、`南宫婉灵动表情/核验`）
   - `<项目>/任务记录/核验-<集号>/`（如 `这就叫专业/任务记录/核验-成片`、`韩老魔的国庆接待/任务记录/核验-E01`）
   - `<项目>/av_align/frames/`、`<项目>/frames/`、`<项目>/*_frames/`（复刻/拆解类项目）
2. **没有上述抽帧 → 从待发布成片抽关键帧**：优先用 `frame-extract` 技能出联系表（OpenCV 直抽，比 ffmpeg 快）挑帧；也可直接 cv2 抽帧。
3. **可叠加一张角色三视图**作身份锚（65535 `input.image` 支持数组，prompt 里按**传入顺序**指认）——但**封面最多 2 张参考**，传多会稀释画风。

> 🔴 用抽帧当参考图前必查三件事：① **8 位 RGB**（10-bit HEVC 来的 48 位 PNG 会让 B站 -111）；② **裁掉平台 UI / 水印 / 字幕带**（核验帧常带）；③ 挑**正脸清晰、动作或情绪最猛**的一帧，**不是首帧**。

**选项 A 的生图提示词 —— 从简（2026-10-11 用户指定）** 🔴

**参考图本身已经承载了身份、场景、影调**，所以**不要再复述长段规格**（五官/发型/服装/光位/构图/负面清单那一大套）——复述反而会和参考图打架、增加漂移。**提示词就一句**：

```
请根据我给的参考图和标题，设计一个封面，标题内容是"<封面标题>"。
标题放在画面下方约 72%-86% 的高度带内、水平居中，宽度不超过画面的 80%，不要被裁切。
```

**第一句照抄即可**；**第二句（文字安全区）是必带的**——因为母图生成后还要裁成两个比例（见下节），不预先规划文字位置、裁完标题就没了。

- **标题文字直接写在提示词里**，让模型出图即带字，省掉后期 `drawtext` 叠字；若中文偶有错字/糊字/字形崩坏，再退回"模型只出主体图 + agent 后期叠字"（做法见选项 B）。
- 🔴 **文字安全区按母图方向写**（这是唯一需要额外补的话）：
  - **竖屏母图**：标题放**下方约 72%–86% 高度带**、水平居中、宽度 ≤80%；主体（人脸）放**上方约 10%–55%**。这样**裁 9:16（裁两侧）与裁 3:4（裁上下）都碰不到标题**。
  - **横屏母图**：标题放**中央偏下**，四周各留 ≥8% 边距；**左下角不放任何文字**（B站会在封面左下角叠播放时长标签）。
- 最多再补一句必要约束（如"不要水印、logo、二维码"）——**保持两三句内**，多余规格一律删掉。
- 参考图仍按上面三级优先级取，**最多 2 张**。
- 模型/规格仍走 65535：`gpt-image-2.5-flare`、横母图 `16:10` / 竖母图 `2:3`、`2k`、`n=1`（**单张提交，不抽卡**）。

🔴 **标题被裁/被挡时不擅自返工**：若裁完之后发现标题被切、被主体压住或文字出错，**先把问题图与裁切结果摆给用户看，由用户决定**（重出母图 / 调文字位置 / 直接用 / 改走选项 B）——**不要自己默默重新生成**（会白花钱）。

### 🔴 平台封面尺寸（2026-10-11 联网核实）

| 平台 | 推荐尺寸 | 比例 | 备注 |
|---|---|---|---|
| B站 | 1146×717（或 1920×1200） | **16:10** | 官方推荐 16:10，**与视频的 16:9 不一样**，需单独出；≤2MB |
| 抖音 | 1080×1920 | **9:16** | 竖版全屏 |
| 快手 | 1080×1920 | **9:16** | 竖版全屏（部分信息流会再裁成约 5:4，关键信息居中） |
| 小红书 | 1080×1440 | **3:4** | 竖版在信息流占屏面积最大，**优先** |

### 🔴 只生成 2 张母图，靠裁剪出全部平台（2026-10-11 用户指定）

**不要每个尺寸各生成一张**。一次只出 **1 横 + 1 竖**，其余靠裁：

| 母图 | 65535 `size` | 裁出 |
|---|---|---|
| **横屏母图** | `16:10` | → **B站** |
| **竖屏母图** | **`2:3`**（9:16 与 3:4 的中间比例） | → **9:16**（抖音/快手，居中裁两侧）＋ **3:4**（小红书，居中裁上下） |

**裁切规则**（脚本 `tools\crop_covers.py --horiz <横母图> --vert <竖母图> --out-dir <目录>`，一次出四张）：

- **9:16** = 竖母图**居中裁两侧**——保留全部高度，宽度砍到 **84.4%**
- **3:4** = 竖母图**居中裁上下**——保留全部宽度，高度砍到 **88.9%**
- **B站** = 横母图居中裁到 16:10，再缩到 1920×1200
- 输出统一 **8 位 RGB JPEG**，命名 `封面_B站/封面_抖音/封面_快手/封面_小红书`（`publish_episode.py` 的 `_cover_for()` 按文件名自动分平台取用）

> 竖母图取 **`2:3`** 而非极端的 9:16 或 3:4：它是两者的**几何中值**，两侧损失最小且均衡（裁 9:16 只丢 7.8% 宽、裁 3:4 只丢 5.6% 高），因此**一张图裁两次都不伤主体**。
> 实测 65535 的 `size` 是**宽松**的：非法值会静默回落到默认 `1536×1024`，`3:4` 会归一到 `896×1200`（1K 档）——所以**写错比例不会报错，只会悄悄出成别的画幅**，每张生成后必须 `Read` 核验真实宽高比。

**两条路都须遵守的规格硬要求**：

- **必须 8 位 RGB PNG/JPG**：10-bit HEVC 来源的 48 位 `rgb48be` PNG 会让 B站 `--cover` 在建稿前直接中止（**-111 教训**）→ 落盘统一 `-pix_fmt rgb24`
- **不从成片截帧当封面**（除非走选项 B 且用户认可）——成片首帧通常不是最佳画面，优先挑"最猛那一帧"（与标题爆点呼应的画面）
- 封面文字：只放**短标题 + 角色名**，≤2 行，字要大、有描边；**与标题口径一致**（同样守「标题风格禁区」）
- **图内文字本身也不得出错**：生成后逐字比对标题原文（多字/少字/错字/乱码都要发现），有错按「选项 A 提示词」末条处理

### 第四步：核验后落盘

生成的封面先 `Read` 目视核验（文字无误、宽高比正确、8 位 RGB），再归档到项目 `images/`（或 `发布/`），命名遵循平台专属优先的约定。文案包「封面」行指向最终采用的图。

## 🔴 写文案/起标题前：先摸清成片到底演了什么（2026-10-11 用户指定）

**不要只凭成片文件名猜内容。** 成片所在目录（集目录）与其上级项目目录里通常有整套相关文档——**先扫一遍再动笔**，从里面取真实剧情、台词、最猛的画面与既有口径。

### 扫描顺序（按序取，够用即停）

| 序 | 位置 | 取什么 |
|---|---|---|
| 1 | 成片同目录的 `剧本/`：`*_剧本.md`、`*_分集剧本.md`、`*_单集剧本_*.md` | 剧情正文、台词、爆点/反转点 |
| 2 | 同目录 `提示词/`：`*_H3提示词.md` | **镜头级画面细节**——subject 定义、`<d>` 台词、场景与动作（**最接近成片实际画面**） |
| 3 | 同目录根级 md：`*_拍摄脚本*.md`、`1.md`/`2.md`… 分段文件 | 分段结构、节拍、镜头顺序 |
| 4 | **上级项目目录**：`<项目>-总纲.md`、`资产清单.md` | 系列设定、选题表、角色名单、热点来源 |
| 5 | `任务记录/`（可含 `核验-*`、`publish_result.json`） | 出片台账、费用、既有发布记录、**以前的标题口径** |
| 6 | 同目录已有的 `*-双平台发布文案.txt`、`发布/` | 同系列既有文案——**沿用其话题习惯与措辞调性** |

> ⚠️ **剧本 ≠ 成片**：出片时提示词可能改过（删镜、换动作、吞句）。**冲突时以 `提示词/` 与实际画面（`核验帧/`）为准**，剧本只作背景。

### 从文档里必取三样，再去套公式

1. **本集最猛的一瞬间**——动作/反转/反差最强的那个点，它就是爆点原料
2. **台词原话与说话人**——能直接摘一句做钩子的，比复述剧情强得多
3. **角色名 + 系列/IP 名**——前者供话题与身份代入，后者是 B站标题后缀

## 用法 A — 完整文案包（项目级发布）

### 工作流

1. **先扫文档摸清内容**（见上节）：读成片同目录 `剧本/` 与 `提示词/`，必要时读项目根 `<项目>-总纲.md`、`资产清单.md`，拿到「最猛一瞬间 + 台词原话 + 角色名」。
2. **过「封面闸门」**（见上节）：在成片同目录搜封面 → 找到即记下路径；**没找到就停下来问用户**（65535 生成 / agent 截帧加字），不得自行凑合。
3. 收集输入：成片信息（路径/时长）、封面路径（相对项目根）、角色、本集看点/钩子、采用的热点（平台+热搜原文+热度；无则明确写「无」）、项目与账号。
4. 先拟两边标题并自查字数与精简度（见「自检清单」），再拟简介，最后定标签/话题。
5. 复制 `templates/文案包模板.txt`，填入内容，落盘到**分集/任务目录根部**，命名与项目约定一致：宫装女友 `E{NN}-双平台发布文案.txt`、歌舞团 `D{NN}-双平台发布文案.txt`、其他项目 `<项目>-<集号>-双平台发布文案.txt`。
6. 落盘后用发布脚本干跑校验解析，再交给发布流程：

```powershell
python d:\work\minimax_h3\tools\publish_episode.py --project <palace|dance> --episode <E01|D01> --dry-run
```

`--dry-run` 能解析出两边标题/简介/标签/话题且无 warning 即合格；零话题、热点缺失等告警必须修复后再发。

### 文案包格式（脚本解析硬要求）

- 两个二级标题块，块标题含平台名即可：`## 一、B 站（账号：…）`、`## 二、抖音（账号：…）`。
- 字段统一写成 `- **标题**：…`、`- **简介**：…`、`- **标签**：a,b,c`；可用反引号包裹值。
- 抖音话题**必须编号列表**，独占多行：

```
- **话题**：
  1. #热点原文
  2. #剧名
  3. #IP
```

  写成单行 `#a #b #c` 可能解析为空，导致零话题发布。
- 头部必须有 `- 封面：` 或 `**封面**：` 行（项目根相对路径或绝对路径）；头部「热点」行写热点原文，无热点写「无」并注明第 1 话题取本集主题。
- 旧式 `【B站】/标题：` 写法解析失败，不要用。

## 用法 B — 即时起名（通用入口）

用户没有走项目流程、只是要一条内容（视频/图文）的标题与标签时用本用法。

**流程**：

1. **先扫文档摸清内容**（见「写文案前」节）：拿到的是视频路径时，先扫其目录与上级项目目录的 `剧本/`、`提示词/`、`<项目>-总纲.md`、`资产清单.md`——**别只凭文件名猜内容**；用户已把内容讲清楚时可跳过。
2. **若要直接发布，过「封面闸门」**（在成片同目录搜封面 → 没有就停下来问用户：65535 生成 or agent 截帧加字）。只是单纯问标题、暂不发布时可跳过。
3. 问清或读取三件事：**平台**（决定字数/标签数）、**内容是什么**（视频讲了啥/画面是什么，最好给出本集最猛的那个瞬间）、**有没有要蹭的热点**（有则给热搜原文）。
4. **选定本集"最猛的一瞬间"**——那个动作/反转/反差最强的点，它就是爆点的原料。
5. 用「爆款标题公式库」**至少选 2 个不同公式各写一条**，各带一个引爆词，给用户 **2—3 条候选**并标注差异（这条走的是哪个公式、钩子是什么、留了什么悬念），让用户挑。
6. 每条候选都过一遍「起名自检法」7 条——**不过的先自己改掉，别把废标题端给用户**。
7. 用户定了之后：**要落盘就问落哪**（默认 `<项目>/<集号>-双平台发布文案.txt`，可套用法 A 模板）；**不落盘就直接把标题/标签交给发布命令**。

**临时发布（无文案包）时**：`publish_episode.py` 与 `sau-upload` 只认 `--title/--desc/--tags` 三个字符串，不认识文案包——所以即时起名可以直接喂给它们（或喂给 `sau` CLI），规范照守、流程不必走。

```
& "D:\work\social-auto-upload\.venv\Scripts\sau.exe" douyin upload-video `
  --account <账号> --file "<成片绝对路径>" `
  --title "<拟好的标题>" --desc "<拟好的简介>" --tags 标签1,标签2
```

> 多账号平台（B站 3 个、抖音 3 个）**发布前必须让用户选账号**，不沿用历史默认值；细节见 `sau-upload` 技能。

## 自检清单（落盘/交付前逐项过）

- **标题 ≤20 字**（全平台，B 站剧名集号后缀不计）；**骨架词含 ≥1 个引爆词**（「起名自检法」第 1—2 条）
- B 站标题主体 ≤20 字且含剧名+集号；抖音标题 ≤20 字、纯钩子无编号；小红书 ≤20 字
- 标题是否**前 6 字就抛出猛料**、**只有一个钩子**、**留了未闭合悬念**、**口语化**（「起名自检法」第 3—6 条）
- 两标题是否删掉可省的信息词；**逐字排查「两个女友/争宠/吃醋/最后却」等噱头剧透词**（对照「标题风格禁区」）
- B 站标签 10—12 个、抖音话题 ≤5 个
- 蹭热点：B 站首标签与抖音第 1 话题是否＝热点原文原样，且与头部「热点」行字面一致
- 话题是否全部有搜索价值（剧名/IP/角色/品类），有无为凑数加的泛词
- 抖音话题是否为编号列表
- **封面闸门已过**：已在成片同目录/`images`/`发布` 搜过封面；找到则路径有效，**没找到必须已问过用户**（65535 生成 or 截帧加字），未擅自凑合；**若走 65535 生成，参考图已按「核验帧 → 成片抽帧」优先级取图**，并已核 8 位 RGB、去平台 UI/水印、非首帧；**提示词已从简（「请根据我给的参考图和标题，设计一个封面，标题内容是…」＋一句文字安全区），没有复述长段规格**
- **封面只出了 2 张母图**（横屏 `16:10` + 竖屏 `2:3`），四平台成品由 `tools\crop_covers.py` 裁出——**没有每个尺寸各生成一张**
- **封面文件**：**8 位 RGB**（非 48 位 rgb48be）、尺寸比例正确（**B站 16:10、抖音 9:16、快手 9:16、小红书 3:4**）、**裁完标题完整未被切**、文字 ≤2 行且守标题口径；**若已裁出问题，是摆给用户决策的，不是自己重出的**
- **内容来源已核**：动笔前扫过成片同目录 `剧本/` 与 `提示词/`（必要时含项目根 `<项目>-总纲.md` / `资产清单.md`），标题与简介描述的内容**与成片一致**，不是凭文件名猜的；剧本与成片冲突时**已以提示词/实际画面为准**

## 边界

- 本技能只产出/修改文案，**并负责发布前的封面检查（「封面闸门」）**；实际投稿、回读、AI 声明、验证码门等走发布脚本与 `sau-upload` 技能。
- 平台账号、成片命名、目录结构随项目而定，向调用方技能确认，不在本技能写死。
- **上游调用方**：`dance`、`palace-girlfriend-trending`、`h3-drama-producer`、`h3-video-replicator` 需要发布文案时均指向本技能。**不发布就不调用。**
