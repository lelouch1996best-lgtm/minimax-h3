# 双平台发布文案（抖音 + B站）

为待发布视频撰写并落盘《双平台发布文案.txt》。本技能是**唯一负责创作文案**的环节；发布脚本只解析文案、不生成创意。任何项目（宫装女友、歌舞团及新增项目）有发布需求时都调用本技能。

## 三条硬要求（用户 2026-09-22 指定）

1. **合规**：标题、简介、标签/话题严格符合各平台规范（字数、数量、格式，见下表），超长必截断或重写。
2. **精简**：标题一句话讲清核心看点/钩子，不堆信息、不写满上限；B 站标题可带剧名+集号，抖音标题纯口语钩子。
3. **精准**：标签和话题少而准，不凑数。**蹭热点时该热点原文必须原样作为话题**（抖音第 1 个话题＝热点标题原文，一字不改/不缩写/不换近义词），否则拿不到该热点流量；无热点则第 1 个话题取本集核心主题。

## 平台规范

| | B站 | 抖音 |
|---|---|---|
| 标题 | ≤80 字；精简，末尾带剧名+集号（如 `｜剧名15`） | ≤30 字（脚本自动截 30）；口语钩子，不带剧名编号 |
| 简介 | 可分段，剧情梗概 + 版权/二创说明；建议含核心关键词 | 一自然段，口语化，前两句抓人；可含话题但话题以列表为准 |
| 标签/话题 | 标签 **10—12 个**，逗号分隔；蹭热点时第 1 个＝热点原文（可含空格）；其余取剧名/IP/角色/品类，宁缺泛标签 | 话题**硬上限 5 个**，多了必乱码；编号列表 `N. #话题`；第 1 个＝热点原文（无热点取本集主题），其余＝剧名 1、IP 1—2、品类 1 |
| 分区 | `--tid 47`（动画·短片/同人） | 无 |
| 封面 | 同一张参考图 PNG，不从成片截帧 | 同左 |
| AI 声明 | 投稿时一次带入（脚本自动） | `--declaration "内容由AI生成"`（脚本自动） |

## 热点取词机械规则（不改词）

含空格只去空格；含 `·｜：，` 取分隔符前主段或去符连体；仍不可用取最长完整短语；超约 20 字在词边界截完整前半；被平台拒或无可搜索性时退化为原题核心原词并在文案包「热点」行注明。热点原文须逐字登记在文案包头部「热点」行，且与抖音第 1 个话题字面一致。

## 工作流

1. 收集输入：成片信息（路径/时长）、封面路径（相对项目根）、角色、本集看点/钩子、采用的热点（平台+热搜原文+热度；无则明确写「无」）、项目与账号。
2. 先拟两边标题并自查字数与精简度（见下「自检清单」），再拟简介，最后定标签/话题。
3. 按下方模板复制 `templates/文案包模板.txt`，填入内容，落盘到**分集/任务目录根部**，命名与项目约定一致：宫装女友 `E{NN}-双平台发布文案.txt`、歌舞团 `D{NN}-双平台发布文案.txt`。
4. 落盘后用发布脚本干跑校验解析，再交给发布流程：

```powershell
python d:\work\minimax_h3\tools\publish_episode.py --project <palace|dance> --episode <E01|D01> --dry-run
```

`--dry-run` 能解析出两边标题/简介/标签/话题且无 warning 即合格；零话题、热点缺失等告警必须修复后再发。

## 文案包格式（脚本解析硬要求）

- 两个二级标题块，块标题含平台名即可：`## 一、B 站（账号：…）`、`## 二、抖音（账号：…）`。
- 字段统一写成 `- **标题**：…`、`- **简介**：…`、`- **标签**：a,b,c`；可用反引号包裹值。
- 抖音话题**必须编号列表**，独占多行：

```
- **话题**：
  1. #热点原文
  2. #剧名
  3. #IP
```

  写成单行 `#a #b #c` 可能解析为空，导致零话题发布。
- 头部必须有 `- 封面：` 或 `**封面**：` 行（项目根相对路径或绝对路径）；头部「热点」行写热点原文，无热点写「无」并注明第 1 话题取本集主题。
- 旧式 `【B站】/标题：` 写法解析失败，不要用。

## 自检清单（落盘前逐项过）

- B 站标题 ≤80 字且含剧名+集号；抖音标题 ≤30 字、纯钩子无编号
- 两标题是否一句话讲清点看点，删掉可省的信息词
- B 站标签 10—12 个、抖音话题 ≤5 个
- 蹭热点：B 站首标签与抖音第 1 话题是否＝热点原文原样，且与头部「热点」行字面一致
- 话题是否全部有搜索价值（剧名/IP/角色/品类），有无为凑数加的泛词
- 抖音话题是否为编号列表；封面行路径是否存在

## 边界

- 本技能只产出/修改文案包；实际投稿、回读、AI 声明、验证码门等走发布脚本与 `sau-upload` 技能。
- 平台账号、成片命名、目录结构随项目而定，向调用方技能确认，不在本技能写死。
