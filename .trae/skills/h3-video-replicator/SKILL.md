# H3 视频复刻流水线

用户提供参考视频，产出：镜头分解表（.md）、剧情大纲（.md）、分集剧情（.md）、分集 H3 提示词（.md）、资产清单（.md）、分集定制工作流（.json）。核心原则：**先拆解、后决策、分级审批——剧情大纲 → 分集剧情 → 分集工作流，一级一级过审；上一级未获用户确认，绝不生成下一级。**

与 `h3-drama-producer` 的分工：那边是"剧情大纲 → 剧本"的正向创作；本技能是"成品视频 → 逆向工程"的复刻，大纲与分集剧情都从像素里还原，不是凭空创作。工作流模板选择与定制的细节两边一致，可互相参考。

## 🔴 强制红线：默认不出字幕

**复刻成片默认不带字幕。** H3 有较大概率把台词当屏上字幕"画"进画面（实测约 1/3 集、17% 台词行），且**提示词压不住**——每集提示词必须逐字写 `No subtitles, captions, or on-screen text appear at any point in the video.`，且原片的字幕/贴字**不写进提示词**（与 `h3-drama-producer` 同规则，详见其附录「已知局限：烧录字幕无法用提示词抑制」）。

- 原片字幕**不作为复刻对象**，只在分解表登记时间段，供后期对齐使用
- 用户明确要求字幕时：成片无字幕版本 + 后期 `ffmpeg drawtext` 叠加，绝不让 H3 自己画
- 出片后按 **0.6s 间隔**裁画面 **0.6H–0.8H** 密集扫描核验，均匀联系表会跨过 0.6—1.7s 的字幕窗口而漏判

## 触发条件

用户给出视频文件（MP4/MOV 等），说"复刻这个视频""还原这个视频""照着这个做""做个同款"等。

## H3 能力边界（决策依据）

| 规格 | 值 |
|---|---|
| 单片时长上限 | 默认应用 t8balance ≤15s；t8balance30 可到 30s 但**不推荐**（2026-10-10 用户反馈出片质量问题） |
| 最大画幅 | 横屏 1344×768（16:9）；竖屏 768×1344（9:16），**方向跟随原视频** |
| 帧率 | 24fps，帧数须落在 17k+5 网格（≡5 mod 17） |
| 帧数换算公式 | `frames = max(5, round(s*24)) + (17 - (max(5, round(s*24)) % 17)) % 17`；实测 5s→124 / 10s→243 / 12.6s→311 / 16.36s→396 / 17.0s→413 / 17.6s→430 / 19.04s→464 |

**集的定义**：一集 = 一次 H3 生成的单元，每集 ≤15 秒（实战稳定档 12.60s / 16.36s 档按 16.5s 实际时长交付）；原视频总时长 ÷ 目标集时长向上取整为集数。

**🔴 帧数一律用公式实算，禁止按 `s×24` 心算**：17k+5 网格意味着**任何声明时长都有溢出尾巴**（声明 16.36s 实际 16.50s），不存在"声明=实际"的时长；且网格有平台区（12.5/12.6/12.7s 同落 311 帧）。写文档时用"帧数→实际秒数"表述，别承诺精确秒数。

**🔴 时长档优先选已验证稳定的档位**：16.36s/396 帧是多次验证的稳定档；含玻璃/反射等易糊场景优先压到 12.60s/311 帧档。自定义档位（如 17.0s→413）没有出片先例，风险自担。

## 分级审批机制（本技能的骨架）

三道关卡，一级一级放行，每道关卡以用户的明确表态为通行证：

| 审批级 | 产物 | 审批粒度 | 通过后解锁 |
|---|---|---|---|
| 第一级 剧情大纲 | 《复刻-剧情大纲.md》 | 全片一次 | 资产检索、分集剧情生成 |
| 第二级 分集剧情 | 《复刻-第N集剧情.md》 | 逐集 | 全部集过审后进入工作流生成 |
| 第三级 分集工作流 | 《复刻N.md》+《复刻-工作流N.json》 | 逐集生成、逐集交付 | 该集出片、成片合并 |

审批规则：

1. **提交方式**：每级产物生成后，先过 Step 1.5 通读自检，再把关键内容直接呈现在对话里（大文件附 computer:// 链接），明确请用户"确认，或提修改意见"，然后停下等回复。**未通过自检的文档不得提交**。
2. **确认的认定**：用户明确说"确认/通过/没问题/继续"才算过审；模糊回应（"嗯""再看看"）必须追问；**不得代替用户确认，不得把沉默当确认**。
3. **修改循环**：用户提修改意见 → 只改当前级 → 重新提交本级审批；改一次提交一次，直到明确通过，不得带病升级。
4. **未过审不生成**：大纲未过审，不写任何分集剧情；集剧情未过审，不生成该集提示词与工作流。宁可等待，不可预生成。
5. **级联作废**：上游改动作废下游——大纲修改后，受影响的集剧情状态重置为"待重审"；集剧情修改后，该集已生成的提示词/工作流作废重做。作废记录写入进度表。
6. **状态落盘**：每次审批结果实时写入《复刻-审批进度.md》；新会话接手时先读它，从第一个未过审层级继续——不重复生成已过审内容，也不跳过未完成的审批。
7. **一级一级推进（默认）**：第二级全部集剧情过审后，才进入第三级工作流生成；第三级内逐集生成、逐集交付。用户明确要求"边审剧情边出工作流"时，可对已过审的集提前放行，并在进度表标注。
8. **用户跳过审批**：用户明确说"跳过审批直接生成"时可以放行，但先提示风险，并在进度表标注"用户跳过审批"。

《复刻-审批进度.md》格式：

```markdown
# 复刻-审批进度

项目：<名称> ｜ 原视频：<路径> ｜ 复刻模式：<模式> ｜ 工作流模板：<模板名>

| 审批级 | 产物 | 状态 | 备注 |
|---|---|---|---|
| 第一级 剧情大纲 | 复刻-剧情大纲.md | ✅ 已确认 | — |
| 第二级 第1集剧情 | 复刻-第1集剧情.md | ✅ 已确认 | — |
| 第二级 第2集剧情 | 复刻-第2集剧情.md | 🔄 修改后待复审 | 服装改红色礼服 |
| 第三级 第1集工作流 | 复刻1.md / 复刻-工作流1.json | ⏳ 待生成 | — |
```

## 流程总览

```
参考视频文件
  → Step 0 元信息探测 + 音画对齐（av_align：镜头切点 + 台词词级时间码 + 声音包络）+ 必要时 frame-extract 补帧
  → Step 1 逐段看图 + 抄台词轴（ASR 只是草稿，烧录字幕才是裁决）+ 说话人归属（三要素）+ 浮层文字清点 → 《镜头分解.md》（事实依据）
  → Step 1.5 交付前通读自检（逻辑与通顺性，不过自检不发）
  → Step 2 询问复刻模式（忠实复刻 / 风格迁移 / 单镜头）
  → Step 3 确认输出目录名
  → 【第一级审批】Step 4 生成《复刻-剧情大纲.md》→ 用户确认
  → Step 5 资产检索 → 《资产清单.md》
  → 【第二级审批】Step 6 逐集生成《复刻-第N集剧情.md》→ 逐集确认
  → 【第三级审批】Step 7 逐集生成《复刻N.md》+《复刻-工作流N.json》→ 逐集交付
  → Step 8 校验 → Step 9 合并（可选）
```

## Step 0 — 元信息与提帧（环境陷阱必读）

1. **元信息**：抽帧脚本启动时会打印 fps / 帧数 / 分辨率 / 时长（OpenCV 读取），无需 ffprobe。
2. **提帧统一调用 `frame-extract` 技能（OpenCV 直抽，不尝试 ffmpeg、不要现写 cv2 脚本）**：

   ```
   python <skills根目录>\frame-extract\scripts\extract_frames.py --video <视频路径> --out <输出目录> --interval 4 --height 480
   ```

   本技能自带的 `scripts\extract_frames.py`（旧 ffmpeg 优先版）已弃用，一律改用 frame-extract。
3. **提帧密度**：≤15s 视频每 2 秒一帧；15—60s 每 4 秒一帧；>60s 每 6—8 秒一帧。相邻帧内容突变处即疑似切镜点，可用 `--times` 在两帧之间补提一帧确认。
4. 帧图统一缩到高 480px 再看，节省 token（`--height 480`）。长视频可加 `--sheet --cols 3` 直接出联系表。
5. **🔴 音画对齐（优先于手工均匀抽帧）**：均匀间隔抽帧天生会跨过镜头切点 → 漏镜头；原片没有硬字幕 → 台词只能靠听，时间码全靠猜。两者都由 `tools/av_align.py` 一次性解决：

   ```
   "C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe" tools/av_align.py ^
     --video <视频> --out-dir <项目目录>\av_align --prompt "<人名/专有名词，简体>"
   ```

   产出《音画对齐表.md》+ `av_align.json` + `frames/`（逐镜头代表帧 + 联系表）：**镜头切点（OpenCV 内容驱动，不靠人猜间隔）＋ 台词轴（whisper 词级时间戳，按 0.35s 静音间隔断句）＋ 声音包络（静音段 = 无台词节拍）** 三条轴按时间码合并。Step 1 的《镜头分解.md》以它为输入：镜头段落已切好，逐段 Read 代表帧填人物/服装/动作/镜头语言，台词列直接抄台词轴。
   - **词级时间戳是关键**：`timestamp_granularities[]=segment` 实测会被 5s 网格吸附（0-5/5-9），`word` 粒度能到 0.1s 级。已默认 word。
   - **`--prompt` 传简体**可把 whisper 输出从繁体拉到简体（实测有效）。
   - 纯音乐素材加 `--music`（禁 prompt + 10s 切段防幻觉歌词）；只想要切镜不花钱就 `--no-asr`。
   - 漏镜 → 调小 `--cut-thresh`（脚本会打印候选切分分数）；误切 → 调大。

## Step 1 — 镜头分解（复刻的事实依据）

用 Read 工具逐帧查看，`target` 写"视频第Ns画面，简述人物、服装、场景、动作、文字"，把观察结果填入《镜头分解.md》：

| 列 | 说明 |
|---|---|
| 镜头号 / 时间段 / 时长 | 由帧位置推断，内容突变即切镜（av_align 已自动切好，直接沿用） |
| 场景 | 地点、光线、背景物（品牌 logo 墙、豪车、人群、闪光灯） |
| 人物 | 人数、发型、妆容、配饰 |
| 服装 | 材质、颜色、剪裁细节，精确到"可照着重制"的程度 |
| 动作 | 每个镜头的核心动作（下车、走红毯、签名、挥手、回眸） |
| 镜头语言 | 景别（特写/半身/全景）、角度（仰拍/平拍）、运动（推/摇/跟随） |
| 台词（音频） | 从《音画对齐表.md》台词轴抄入：起止时间码 + 原文；**没有人声就写"无台词，环境音"**。有烧录字幕的原片：抄入前必须按下方「台词轴校验」逐句目视校对，以字幕为准。**每句同时按下方「台词与动作同帧绑定」记录说话时动作** |
| 说话人 | 按下方「说话人归属」三要素判定；每句标置信度（✅字幕确证 / 👄口型验证 / 📖语境推断 / ⚠️待核），禁止只凭台词语义猜归属 |
| 画面文字 | 分三类：实体文字（名牌/招牌/logo 墙）、字幕贴字、噪声水印（判定见下） |
| 内容/噪声判定 | 见下方规则 |

**画面文字判定规则**：画面内文字分两类，处理方式**不同**——
- **实体文字**（招牌、木牌、账本、人物名牌、品牌 logo 墙、立牌等真实存在于场景中的物件上的字）→ 标"内容-复刻"，写入提示词时保留原文、语言与位置
- **字幕/贴字**（口播字幕、硬字幕、进度条式贴字、综艺花字）→ 🔴 **默认剔除**，标"字幕-剔除"，**不写入提示词**（详见下方「🔴 强制红线」）；需要字幕时统一后期叠加
- **噪声**（录屏软件水印、播放器 UI：进度条、时间戳、按钮、平台图标、压缩伪影）→ 标"噪声-剔除"，绝不 入词

分解表末尾写全片总结：色彩体系、平均镜头时长与转场节奏、贯穿母题/固定元素（如反复出现的品牌墙、同款实体名牌样式）、人物出场顺序表。字幕只登记时间段（供后期对齐），不作为风格锚点。**封闭空间戏（车内/房间/办公室，90% 镜头在同一空间）必须额外画出空间布局图：人物座位/站位、机位、画面里能看到谁——空间不定死，台词归属与后续提示词的调度全是猜。全片总结还需给出台词预算：每句时长与字数、实际发声累计、台词占用率（发声累计÷总时长）与每秒字数（>6字/秒标"连读"）。**

### 🔴 台词轴校验：ASR 只是草稿，烧录字幕才是最终裁决

whisper 台词轴在中文短剧上错误率不可接受（实测错例：老登爹→老发爹、翘头→撬头、舔狗罢了→甜狗爸了、彩礼→才礼、**没钱不怕→没钱不放——一词之差直接改写人物立场**）。原片有烧录字幕时，**每句台词必须目视校对后才能定稿**：

1. 对每句台词的时间点用 frame-extract 补提帧（`--times` 精确到台词中点）
2. 裁字幕带（画面底部 0.78H–1.0H 区域）放大目视；直接 Read 整帧也行，裁带放大更准
3. 凡字幕可辨认处一律以字幕为准；**ASR 与字幕冲突时永远信字幕**——不能因为 ASR 听起来像就放过，哪怕语义也"说得通"
4. 台词轴把两句连读粘成一句时（一长句语速 >6字/秒），抽查中间点的字幕帧确认是否为两条独立字幕——是则拆成两句并标"连读，中间不停顿"，防止下游配音/提示词误加停顿
5. 字幕被前景遮挡的句子：前后各 ±0.3s 再抽两帧；仍看不到就标 ⚠️ 待核，绝不按 ASR 听感定稿

### 🔴 说话人归属：三要素交叉验证，台词语义不作为判定依据

**台词归属是剧情的函数，不是独立变量**——去掉站位和动机，"谁说的"本身就无从判断。判定顺序：

1. **先定空间调度，再判归属**：多人同框的对话戏（车内戏尤其）必须先画座位布局/站位/机位——谁在哪、镜头从哪拍、画面里能看到谁
2. **每句台词用三要素交叉验证**：
   - **口型**：说话瞬间抽密集帧（0.2–0.4s 间隔）看谁嘴唇张合——最硬的证据
   - **视线朝向**：听者看向谁、说话人转头对着谁
   - **画面在场**：台词瞬间谁在画面里（画外音 VO 除外）
   三者一致才可定稿；只有语义推断没有画面佐证的标 ⚠️ 待核
3. **置信度优先级：用户指正 > 画面证据 > 语境推断 > ASR 听感**。用户看过片、了解剧情，其指正优先级最高；拿到指正后仍要回画面验证——能证实就标"已确证"，证不了就保留用户判断并注明"依据用户口述"
4. **字幕挂错画面（剪辑错位）**：按台词内容 + 口型归属，不按字幕所在帧归属——短剧剪辑错位常见
5. **反转的"表演层"必须显式记录**：有反转的片子（如"演戏给某人看"），哪句话是说给谁听的表演、哪句是真话，写进分解表备注——丢了这层，下游剧情大纲会把反转拍成直给

### 台词与动作同帧绑定（分解表层面，防止"台词台账"）

验证口型的密集帧**同时就是动作证据**——看帧判归属的那一刻，把"说话人说这句时在干什么"一并记进分解表：姿态（靠坐/探身/转头）、手势（指谁/摊手/拍油箱）、表情（得意/隐忍/僵硬）、朝向（对谁说）。规则：

1. **一句一记，不按镜头笼统记**：一个镜头多句台词（车内戏一个机位十几句）时，镜头级"动作"列覆盖不了每句的表演，必须逐句记
2. 台词列格式建议：`时间码 说话人（说话时动作/表情/朝向）：台词`
3. **台词不挂动作 = 下游必然编造**：分集剧情写剧本时发现台词没挂动作，只能凭空补表演——凭空补的就是编造，违反证据纪律；正确做法是回 Step 1 补帧重记，不是在剧情里脑补

### 证据纪律（分解表与所有下游文档统一执行）

- **绝不描述没有看到的画面**：能看到的写实情，看不到的标 ⚠️ 待核，推断的写明推断链——三者绝不混写
- 待核项单独成清单随分解表提交，请用户裁决；**宁可留白，绝不编造**
- 用户转述的内容与画面观察分开标注来源（"画面所见" / "用户口述"）

### 浮层文字清点（字幕、实体文字之外的第三类画面文字）

黄色反讽字、综艺花字、旁白贴字这类**浮层提示**（如「以为她父亲是司机」「此时的精神小伙」「精神男友来了」）既不是实体文字也不是口播字幕，**极易漏记**。逐帧看图时必须专门清点：出现时间、位置、原文、作用（反讽/介绍人物登场/点题）。浮层文字按"字幕-剔除"处理（不写入提示词），但必须登记入分解表——它是原片叙事节奏的一部分，复刻时用户可能要后期重做同款浮层。

## Step 1.5 — 交付前通读自检（不过自检不发用户）

**任何剧本、分解表、剧情文档在提交审批前，必须先自己以观众视角从头通读一遍**，检查逻辑与通顺性。通读清单：

1. **对话接得上吗**：每句问答是否呼应——问"他"答"她"式的指代错位，是归属判错或台词抄错的信号
2. **人物位置连续吗**：相邻两句之间人物有没有瞬移（上一句在车外、下一句突然在车内，中间缺动作节拍 = 分解表漏了调度）
3. **动机链完整吗**：每个关键转折（发怒、定局、反转）的前一句是否给了充分诱因；接不上说明有句话归属错了或漏抄了
4. **反转支点写实了吗**：有反转的片子，"谁在演给谁看"必须显式写明，否则下游提示词会把反转拍成直给
5. **时间码单调递增、无重叠；每句都有说话人与置信度标注**

发现断点：回到 Step 1 补画面证据（抽帧/口型/字幕带核验），修完**重新通读**，通不过不发。

**"台词台账"式文档（只有谁说了什么、没有人在哪在干什么）是已被验证的错误做法**：归属判断错率约 10%，用户会要求全部重写。台词必须挂在站位、动作、情绪上才构成剧本。

## Step 2 — 询问复刻模式（必须先问，不问不许生成）

| 模式 | 做法 | 适用 |
|---|---|---|
| 忠实复刻 | 人物、服装、场景、分镜全部按原视频 | 原视频人物有三视图资产，或用户自己有 |
| 风格迁移（默认推荐） | 保留分镜结构、镜头语言、节奏与氛围，人物/品牌换成用户自己的 | 无原人物资产，或规避版权 |
| 单镜头复刻 | 只挑 1—3 个镜头重做 | 试片、验证风格 |

用户未选时**主动推荐风格迁移**并说明理由，确认后再继续。

## Step 4 — 生成剧情大纲【第一级审批】

基于《镜头分解.md》与已确认的复刻模式，生成《复刻-剧情大纲.md》，内容五块：

1. **全片故事梗概**：原视频的完整叙事——人物、目标、冲突、结局。只写镜头分解表里看得到的事实，不脑补。
2. **复刻版故事映射**：忠实复刻 → 照搬原故事；风格迁移 → 写明替换后的人物/品牌，以及保留的分镜结构、镜头语言、节奏与氛围；单镜头复刻 → 只写所选 1—3 个镜头的故事。
3. **分集一览表**：集号 / 对应原视频时间段 / 时长 / 集标题 / 一句话核心事件 / 本集结尾钩子 / 本集台词预算（句数·字数）。按原视频天然镜头段落切，不硬切；**拆集不得切断一句台词**，每集台词量须装得进该集时长（≤5字/秒）。
4. **跨集锚点**：固定色彩体系、实体文字元素（名牌/招牌/logo 墙）样式、贯穿道具/母题、人物造型延续。**字幕不在锚点之列**（默认不出字幕）。
5. **整体节奏与情绪曲线**：平均镜头时长、转场风格、情绪走向。

生成后**当场提交第一级审批**：在对话里呈现大纲（分集一览表必须完整展示），明确请用户确认或提修改意见。用户提意见就改，改完重新提交；获明确确认后在《复刻-审批进度.md》记录，才进入 Step 5。

## Step 5 — 资产检索与清单

大纲过审后人物清单已定，立即按人物名找三视图（同 `h3-drama-producer` Step 5）。本技能在**多台电脑上使用**，资产目录不固定，按候选列表依次探测，存在的目录都可用：

| 优先级 | 候选资产根目录 | 说明 |
|---|---|---|
| 0 | 用户当场指定的目录 | 永远最优先 |
| 1 | `D:\work\fanrenCharacter\` | 新资产库（新电脑） |
| 2 | `E:\短剧平台\凡人二创\人物图\` | 旧资产库（旧电脑），仍可使用 |

- **探测**：逐个候选根目录 `Test-Path` 判断是否存在，记下全部存在的根目录（一台机器上可能只有一个，也可能新旧并存）
- **检索**：对每个人物，在所有存在的根目录里按人物名匹配文件夹，再找三视图：

  ```powershell
  Get-ChildItem <根目录> -Recurse -Directory | Where-Object Name -like "*<人物名>*" | ForEach-Object { Get-ChildItem $_.FullName -Recurse -File -Filter "*三视图*" }
  ```

- 多个根目录都找到同一人物时：列出各处结果请用户选；用户不表态则取优先级最高的一处，并在清单中注明其余备选位置
- 找到后用 Read 工具查看图片内容，把实际形象写入清单
- 同一人物多张三视图时必须先问用户选哪张
- 忠实复刻模式下找不到原人物三视图：如实标注"未找到"，并给用户两条路——改走风格迁移模式，或先用生图工具为该人物做三视图再回来
- 输出 `资产清单.md`：人物、文件名、绝对路径、**来源根目录**、外观说明、与 <Picture N> 的对应关系
- **跨电脑迁移**：换电脑后《资产清单.md》里的绝对路径可能失效。接手旧项目时先逐条 `Test-Path`，失效条目按候选列表重新探测并更新清单（人物与外观不变，只换路径），已过审的剧情内容不动

资产就绪后，分集剧情与提示词里的服装描述一律以清单里的实际形象为准。

## Step 6 — 分集剧情【第二级审批，逐集进行】

逐集生成《复刻-第N集剧情.md》，每集包含：

- 集号 / 对应原视频时间段 / 时长 / 集标题
- **本集台词预算**：本集台词总句数、总字数、总发声时长、每句时长与字/秒；台词占用率 >90% 时明确标注"**逐句照搬即可撑满时长，加词必超**"。提示词的对白量以本集台词为准，不得增删（按每秒 4—5 个汉字估算；时长必须由台词总需时倒推，见 Step 7 写词红线第 6 条）
- **本集剧情详述**：起承转合小弧线——本集开场可独立理解、结尾有钩子或收束。**必须写成可拍摄的剧本段落，不是事件梗概**：每句台词标注说话人与情绪/动作（`角色名（情绪/动作）：台词` 的短剧格式），关键调度（谁在哪、走向谁、按住谁、视线朝向）必须写明；只列"谁说了什么"的台词台账会丢失反转的表演层，已被验证为错误做法
- **本集空间设定**：封闭空间戏（车内/房间）引用镜头分解表的空间布局图；台词归属随空间走
- **镜头级内容表**：从《镜头分解.md》摘出本集全部镜头（场景/人物/服装/动作/镜头语言/画面文字），沿用"内容-复刻 / 噪声-剔除"标注
- **人物形象**：服装描述引用《资产清单.md》的实际形象
- **跨集衔接**：承接上一集的元素、留给下一集的钩子
- **声音与氛围**：需要的 BGM/人声情绪（按镜头分解的情绪描述对齐；录屏噪声不复刻）

逐集审批：生成一集 → 在对话里呈现该集剧情 → 用户确认或提修改 → 状态写入《复刻-审批进度.md》。该集过审前不生成其提示词与工作流；全部集过审后才进入 Step 7（用户明确要求边审边出工作流的除外）。

## Step 7 — 分集工作流【第三级审批，逐集生成】

只处理**已过审**的集。第一次执行前先做一次性决策：

**模板选择**：扫描 `d:\work\minimax_h3\工作流模板\` 列出模板并询问用户，选定后各集沿用。

然后逐集生成（对每个已过审的集，按顺序）：

1. 调用 `h3-prompt-writing` 技能生成《复刻N.md》（时长 4—16 秒灵活，按 Step 6 分集剧情确定的时长写作，时长体现在帧数与 0—Ns 时间线；含玻璃/反射等易糊场景优先压到 12.60s 档），并遵守下方「Step 7 写词红线」全部 6 条

2. 提示词的人物服装、场景、动作、镜头语言必须与该集《复刻-第N集剧情.md》和《镜头分解.md》逐条对应，不得凭空想象
3. **画幅方向跟随原视频**：竖屏原片用 H3 竖屏画幅（768×1344 / 9:16），横屏用 1344×768；t8 模板走 ResolutionSelector 的 Portrait 档
4. **🔴 画面文字分级处理（默认不出字幕）**：只有**实体文字**（招牌、木牌、账本、名牌、logo 墙）才写入提示词并保留原文与位置；**字幕/贴字一律不写入提示词**，标"字幕-剔除"；录屏噪声（水印、播放器 UI）同样绝不入词。每集提示词必须逐字含 `No subtitles, captions, or on-screen text appear at any point in the video.`
5. 忠实复刻时若原视频带背景音乐/人声且用户需要，声音设计按镜头分解的情绪描述对齐；录屏噪声（电流声、UI 音效）不复刻
6. 定制该集工作流 JSON（同 `h3-drama-producer` Step 6/7）：填提示词、锁定分辨率（竖屏片锁 768×1344）、设帧数、接 LoadImage 参考图槽、改输出前缀 `MiniMaxH3/<复刻项目名>`；提示词为 `h3-prompt-writing` 生成的 Ref2VA 六段结构，直接填入工作流节点；参考图经 runninghub 上传后回填文件名（上传链接仅一天有效）
7. 生成后用 computer:// 链接交付该集，在《复刻-审批进度.md》标记"已交付"；用户对成品提修改时只回改该集提示词/工作流，不波及其他集

## 🔴 Step 7 写词红线（每条都有翻车→修复→出片验证）

1. **🔴 一集只留一种镜头类型，混切就拆集**：H3 一次连续生成内做「车内→车外→回车内」等多类型切换会崩——人物错位、后段退化成糊块、末句台词被吞（实测：声明 `cut outside` 但成片里那个 Shot 仍是原机位的人）。**提示词里绝不写任何 "cut outside"**；跨空间叙事正解 = 截短本集 + 把尾段台词移交下一集开头（已验证的移交模式）。
2. **🔴 跨座位动作必穿模，写"扭上身、不离座"**：写"驾驶座伸手到后排揪领"（reaches back across）→ 模型把人整个搬到后排。双重声明修复（已验证有效）：动作写 `Without leaving his seat, twists his upper body back — hips and legs staying planted`；subject 定义写死 `stays seated in the driver's seat for the whole video and never leaves it`。
3. **🔴 "哪扇窗/哪个门"必须显式写死**：泛写"敲车窗"模型会随机放到后排车门（实测敲窗戏落在后窗）。正解：`a knock-knock sounds from the FRONT passenger-side window — the window directly beside <Subject 2> in the front seat, not the rear door window`。
4. **🔴 静置定格 ≤1.5s（玻璃/反射场景）**：定格 >2s 末端高概率糊化（实测 16.6–17.9s 灰糊）。缓拉/推移长镜的"最后静止"指令模型常不遵守 → 交给**后期定格**；核验是否真静止要算帧差（<5 才算停）。
5. **🔴 台词逐句绑定说话人**：每句写 `<Subject N>'s mouth moves as he/she says <d>[Chinese]…</d>`，同框他人写 `mouth stays closed and still`；四类必标：画外音（写明"画面 Y 嘴闭合"）、背影台词、换气点（≥0.3s）、无台词角色（`lips stay closed and still` + soundscape `completely silent`）。自检 `grep -c "mouth moves"` ≈ 台词句数。
6. **🔴 时长由台词总需时倒推**：`最短时长 ≈ Σ(字数÷5字/秒) + Σ句间气口0.35s + 开场留白0.6s`，先算再选时长档，最后写镜头时间戳；时间戳必须与台词落点对齐，否则嘴型与声音错配。
7. **🔴 座位/站位必须逐人写死并全片锁死**：不写死时 H3 会让每个人的座位在集内漂移（时而在驾驶座、时而在后排；多人换位）。修复配方（2026-10-10 黄毛项目实测）：空间布局定稿后，**每个 subject 的定义句都带全片锁**——`<Subject 2> remains seated in the front passenger seat for the whole video, never changing seats`、`<Subject 3> stays in the rear seat directly behind the driver for the whole video`；summary 与 retention_analysis 各再重申一遍全片座位表（"Seating is fixed: … never swaps"）。跨座位动作另遵守第 2 条（扭上身不离座）。
8. **🔴 车窗/车门开闭状态必须显式声明恒定**：不声明时模型会在集内随机翻转（窗时开时关、门时闭时开）。修复配方：**一个状态、一句话、写死全片**——`the FRONT passenger-side window stays CLOSED for the entire video and is never rolled down`（或 `stays fully rolled down from the first frame to the last`），车门同理 `the car doors remain closed throughout`；需要"窗从关到开"的原片剧情状态变化时，写明确切变化时刻 `stays closed until 00:07.5, then rolls fully down and remains open to the end`——**除该时刻外整段声明不变**。

## Step 9 — 成片合并（可选）

H3 单片上限 15 秒（t8balance 默认应用）；超长原视频拆集生成，出片后再合并。若各集由**同一工作流模板、同一分辨率、同一编码参数**生成，优先使用 ffmpeg `concat` + `-c copy` **流拷贝**拼接：不重新编码、秒级完成、画质无损。

使用本技能自带的合并脚本：

```
python <本技能目录>\scripts\merge_segments.py --list segments.txt --out final.mp4
```

其中 `segments.txt` 每行写一集绝对路径：

```
file 'D:\work\minimax_h3\复刻项目\红毯复刻1.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻2.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻3.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻4.mp4'
```

注意事项：
- 各集分辨率、帧率、编码器必须一致，否则 `-c copy` 会失败或产生异常；脚本会先 probe 检查，不一致时拒绝并提示转码合并命令
- 如需加统一 BGM / 字幕，在合并后的成片上用 ffmpeg（`drawtext` / `concat`）二次处理；合并脚本只做无损失的集间拼接。**字幕永远走后期叠加，不让 H3 生成**
- 合并脚本同样继承 Step 0 的 ffmpeg 自动探测逻辑，找不到可用 ffmpeg 时回退到 OpenCV 软合并（慢且有损，仅应急）

## 需要发布时（指向发布文案技能）

复刻成片备好后若用户要发布（抖音/B站等），**标题/简介/标签/话题一律调用 `publish-copywriting` 技能撰写**，不要临场手拟：

- 该技能是**唯一的文案创作环节**，规范（平台字数、标签数、标题禁区——禁「两个女友/争宠/最后却…」类噱头剧透）以其为权威
- 产出《<复刻项目名>-双平台发布文案.txt》落盘项目根部，再由 `tools\publish_episode.py` 解析发布
- **临时发单条、无文案包时同样适用**：仍按该技能的口径拟标题与标签（`publish_episode.py` 与 `sau-upload` 只认 `--title/--desc/--tags`，不生成创意）
- **封面也要过闸门**：发布前先走 `publish-copywriting` 的「封面闸门」——在成片同目录搜封面，没有就**主动问用户**（65535 生成 / agent 截帧加字），**不得用参考图默默凑合**；**若走 65535 生成，参考图优先复用本片核验时截的抽帧（`核验帧/`、`av_align/frames/`），没有再从成片抽关键帧**
- **调用时交出内容线索**：把**成片路径**连同同目录 `剧本/`/`提示词/`（复刻项目还有 `_镜头分解.md`、`音画对齐表.md`）与项目根 `资产清单.md` 的位置一并告诉文案技能——它会据此摸清剧情再动笔；**别只丢一个文件名**
- **不发布就不调用**：本技能只到成片交付为止，文案技能按需触发
