# H3 视频复刻流水线

用户提供参考视频，产出：镜头分解表（.md）、分段 H3 提示词（.md）、资产清单（.md）、定制工作流（.json）。核心原则：**先拆解、后决策，每一步动手生成之前先把关键决策问清楚，绝不跳步生成。**

与 `h3-drama-producer` 的分工：那边是"剧情大纲 → 剧本"的正向创作；本技能是"成品视频 → 逆向工程"的复刻，素材来源是像素不是文字。Step 6 之后的流程两边一致，可互相参考。

## 触发条件

用户给出视频文件（MP4/MOV 等），说"复刻这个视频""还原这个视频""照着这个做""做个同款"等。

## H3 能力边界（决策依据）

| 规格 | 值 |
|---|---|
| 单片时长上限 | 15 秒（另有 5s / 10s 档） |
| 最大画幅 | 横屏 1344×768（16:9）；竖屏 768×1344（9:16），**方向跟随原视频** |
| 帧率 | 24fps，帧数须落在 17k+5 网格 |
| 常用帧数换算 | 5s→124 帧，10s→243 帧，15s→362 帧 |

## 流程总览

```
参考视频文件
  → Step 0 元信息探测 + 提帧（ffmpeg / OpenCV）
  → Step 1 逐帧看图 → 《镜头分解.md》
  → Step 2 询问复刻模式（忠实复刻 / 风格迁移 / 单镜头）
  → Step 3 分段规划（>15s 时）
  → Step 4 确认输出目录名
  → Step 5 调用 prompt 技能生成提示词 → 《复刻N.md》逐段落盘
  → Step 6 检索人物三视图 → 资产清单.md
  → Step 7 列出工作流模板，询问用户选哪个
  → Step 8 按模板定制工作流 JSON（图片经 runninghub 上传）
  → Step 9 校验 → 交付
```

## Step 0 — 元信息与提帧（环境陷阱必读）

1. **元信息**：`ffprobe` 读分辨率、帧率、时长，判断横竖屏与总时长。
2. **提帧用本技能自带脚本，优先 ffmpeg、自动回退 OpenCV**：脚本会先探测 PATH 及常见位置的 ffmpeg，并用一个 32×32 黑帧 probe 验证该 ffmpeg 真的能写图片；验证通过才用 ffmpeg 提帧，否则自动回退到 OpenCV。本机存在两个 ffmpeg：TRAE 自带版（在 PATH，不能写 image2 序列）和录屏软件附带版（不在 PATH，能正常输出 png/jpg），脚本会自动选择能用的那一个。

   ```
   python <本技能目录>\scripts\extract_frames.py --video <视频路径> --out <输出目录> --interval 4 --height 480
   ```

   可选参数：
   - `--backend ffmpeg`：强制只找 ffmpeg，找不到就报错
   - `--backend opencv`：强制用 OpenCV

3. **提帧密度**：≤15s 视频每 2 秒一帧；15—60s 每 4 秒一帧；>60s 每 6—8 秒一帧。相邻帧内容突变处即疑似切镜点，可在两帧之间手动补 `--start` 再提一帧确认。
4. 帧图统一缩到高 480px 再看，节省 token。

## Step 1 — 镜头分解（复刻的事实依据）

用 Read 工具逐帧查看，`target` 写"视频第Ns画面，简述人物、服装、场景、动作、文字"，把观察结果填入《镜头分解.md》：

| 列 | 说明 |
|---|---|
| 镜头号 / 时间段 / 时长 | 由帧位置推断，内容突变即切镜 |
| 场景 | 地点、光线、背景物（品牌 logo 墙、豪车、人群、闪光灯） |
| 人物 | 人数、发型、妆容、配饰 |
| 服装 | 材质、颜色、剪裁细节，精确到"可照着重制"的程度 |
| 动作 | 每个镜头的核心动作（下车、走红毯、签名、挥手、回眸） |
| 镜头语言 | 景别（特写/半身/全景）、角度（仰拍/平拍）、运动（推/摇/跟随） |
| 画面文字 | 字幕卡、人物名牌、品牌 logo 墙、水印 |
| 内容/噪声判定 | 见下方规则 |

**噪声剔除规则**（录屏素材必查）：录屏软件水印、播放器 UI（进度条、时间戳、按钮）、平台图标、压缩伪影**不属于复刻对象**，在"画面文字"列标"噪声-剔除"；原视频自带的字幕卡、人物名牌、品牌 logo 墙属于内容元素，标"内容-复刻"，生成提示词时要写明文字内容、语言与位置。

分解表末尾写全片总结：色彩体系、平均镜头时长与转场节奏、贯穿母题/固定元素（如反复出现的品牌墙、同款字幕卡样式）、人物出场顺序表。

## Step 2 — 询问复刻模式（必须先问，不问不许生成）

| 模式 | 做法 | 适用 |
|---|---|---|
| 忠实复刻 | 人物、服装、场景、分镜全部按原视频 | 原视频人物有三视图资产，或用户自己有 |
| 风格迁移（默认推荐） | 保留分镜结构、镜头语言、节奏与氛围，人物/品牌换成用户自己的 | 无原人物资产，或规避版权 |
| 单镜头复刻 | 只挑 1—3 个镜头重做 | 试片、验证风格 |

用户未选时**主动推荐风格迁移**并说明理由，确认后再继续。

## Step 3 — 分段规划

- 每段不超过 15 秒；原视频总时长 ÷ 15 向上取整为段数
- 每段必须有独立完整的小弧线（本段开场可理解、结尾有钩子或收束），按原视频的天然镜头段落切，不硬切
- 设计跨段锚点保证连续感：固定色彩体系、固定字幕卡样式、贯穿道具/母题、同一人物造型
- 分段方案先向用户展示（段数、每段对应原视频时间段、核心事件、锚点），认可后再进入生成

## Step 4 — 确认输出目录

正式输出前与用户确认目录名，默认：

```
d:\work\minimax_h3\<复刻项目名>\
```

目录内最终交付物：

```
镜头分解.md          Step 1 产物，全部提示词的事实依据
复刻N.md             每段一份完整提示词
复刻-分段总纲.md     分段结构表 + 跨段锚点 + 全部提示词
资产清单.md          人物三视图路径与用途
复刻-工作流.json     定制工作流（按所选模板，可有多份）
merge_segments.py    可选：H3 各段出片后用 ffmpeg concat 流拷贝合并成片
```

## Step 5 — 生成提示词

按每段时长调用对应子技能（不要用错时长版本）：

| 单段时长 | 调用技能 |
|---|---|
| 5 秒 | `minimax-h3-prompt` |
| 10 秒 | `minimax-h3-prompt-10s` |
| 15 秒 | `minimax-h3-prompt-15s` |

- 每段提示词的人物服装、场景、动作、镜头语言必须与《镜头分解.md》逐条对应，不得凭空想象
- **画幅方向跟随原视频**：竖屏原片用 H3 竖屏画幅（768×1344 / 9:16），横屏用 1344×768；t8 模板走 ResolutionSelector 的 Portrait 档
- 原视频画面内可见文字（字幕卡、名牌、logo 墙）写入提示词时保留原文与位置
- 忠实复刻时若原视频带背景音乐/人声且用户需要，提示声音设计按镜头分解的情绪描述对齐；录屏噪声（电流声、UI 音效）不复刻

## Step 6 — 资产检索与清单

按剧本中出现的人物，去资产目录按**人物名找三视图**（同 `h3-drama-producer` Step 5）：

- 默认资产目录：`E:\短剧平台\凡人二创\人物图\<人物名>\`（以用户实际指定为准）
- 检索方式：`Get-ChildItem <资产目录> -Recurse -File -Filter "*三视图*"`，按人物名匹配文件夹
- 找到后用 Read 工具查看图片内容，把实际形象写入清单，并据此修正提示词服装描述
- 同一人物多张三视图时必须先问用户选哪张
- 忠实复刻模式下找不到原人物三视图：如实标注"未找到"，并给用户两条路——改走风格迁移模式，或先用生图工具为该人物做三视图再回来
- 输出 `资产清单.md`：人物、文件名、绝对路径、外观说明、与 @图片N 的对应关系

## Step 7 / Step 8 — 工作流模板选择与定制

同 `h3-drama-producer` Step 6/7：扫描 `d:\work\minimax_h3\工作流模板\` 列出模板并询问用户；定制时填提示词、锁定分辨率（竖屏片锁 768×1344）、设帧数、接 LoadImage 参考图槽、改输出前缀 `MiniMaxH3/<复刻项目名>`；T8 模板走 `h3-prompt-writing` 六段结构；参考图经 runninghub 上传后回填文件名（上传链接仅一天有效）。

## Step 9 — 校验清单（生成后必做）

- [ ] 镜头分解表"噪声"项（录屏水印、播放器 UI）未进入任何提示词
- [ ] 每段提示词与镜头分解表逐条对应（服装/场景/动作/镜头语言/画面文字）
- [ ] 画幅方向与原视频一致，分辨率已锁定
- [ ] 提示词 @图片N 引用行与 LoadImage 数量、顺序一致；时间段无缺口覆盖 0—Ns
- [ ] T8 版六段结构齐全、[Shot N] 与时间戳格式正确、对白格式齐全
- [ ] 链路完整：links 两端互指一致、无悬空引用、被删节点无残留
- [ ] 帧数正确（5s→124 / 10s→243 / 15s→362）；last_node_id / last_link_id 已更新；JSON 可解析

## Step 10 — 成片合并（可选）

H3 每段最多 15 秒，超过 15 秒的原视频需要拆段生成，出片后再合并。若各段由**同一工作流模板、同一分辨率、同一编码参数**生成，优先使用 ffmpeg `concat` + `-c copy` **流拷贝**拼接：不重新编码、秒级完成、画质无损。

使用本技能自带的合并脚本：

```
python <本技能目录>\scripts\merge_segments.py --list segments.txt --out final.mp4
```

其中 `segments.txt` 每行写一段绝对路径：

```
file 'D:\work\minimax_h3\复刻项目\红毯复刻1.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻2.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻3.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻4.mp4'
```

注意事项：
- 各段分辨率、帧率、编码器必须一致，否则 `-c copy` 会失败或产生异常；脚本会先 probe 检查，不一致时拒绝并提示转码合并命令
- 如需加统一 BGM / 字幕，在合并后的成片上用 ffmpeg 或剪辑软件二次处理；合并脚本只做无损失的段间拼接
- 合并脚本同样继承 Step 0 的 ffmpeg 自动探测逻辑，找不到可用 ffmpeg 时回退到 OpenCV 软合并（慢且有损，仅应急）

## 交付规范

- 每个文件用 computer:// 链接交付，附一句话说明
- 交付时列出分段对照表：段号 ↔ 原视频时间段 ↔ 核心事件
- 主动建议下一步：选段跑工作流、调提示词、换模板、换复刻模式重跑
