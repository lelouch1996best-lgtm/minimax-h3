# H3 视频复刻流水线

用户提供参考视频，产出：镜头分解表（.md）、剧情大纲（.md）、分集剧情（.md）、分集 H3 提示词（.md）、资产清单（.md）、分集定制工作流（.json）。核心原则：**先拆解、后决策、分级审批——剧情大纲 → 分集剧情 → 分集工作流，一级一级过审；上一级未获用户确认，绝不生成下一级。**

与 `h3-drama-producer` 的分工：那边是"剧情大纲 → 剧本"的正向创作；本技能是"成品视频 → 逆向工程"的复刻，大纲与分集剧情都从像素里还原，不是凭空创作。工作流模板选择与定制的细节两边一致，可互相参考。

## 触发条件

用户给出视频文件（MP4/MOV 等），说"复刻这个视频""还原这个视频""照着这个做""做个同款"等。

## H3 能力边界（决策依据）

| 规格 | 值 |
|---|---|
| 单片时长上限 | 15 秒（另有 5s / 10s 档） |
| 最大画幅 | 横屏 1344×768（16:9）；竖屏 768×1344（9:16），**方向跟随原视频** |
| 帧率 | 24fps，帧数须落在 17k+5 网格 |
| 常用帧数换算 | 5s→124 帧，10s→243 帧，15s→362 帧 |

**集的定义**：一集 = 一次 H3 生成的单元，每集 ≤15 秒；原视频总时长 ÷ 15 向上取整为集数，总时长 ≤15s 即单集复刻。

## 分级审批机制（本技能的骨架）

三道关卡，一级一级放行，每道关卡以用户的明确表态为通行证：

| 审批级 | 产物 | 审批粒度 | 通过后解锁 |
|---|---|---|---|
| 第一级 剧情大纲 | 《复刻-剧情大纲.md》 | 全片一次 | 资产检索、分集剧情生成 |
| 第二级 分集剧情 | 《复刻-第N集剧情.md》 | 逐集 | 全部集过审后进入工作流生成 |
| 第三级 分集工作流 | 《复刻N.md》+《复刻-工作流N.json》 | 逐集生成、逐集交付 | 该集出片、成片合并 |

审批规则：

1. **提交方式**：每级产物生成后，把关键内容直接呈现在对话里（大文件附 computer:// 链接），明确请用户"确认，或提修改意见"，然后停下等回复。
2. **确认的认定**：用户明确说"确认/通过/没问题/继续"才算过审；模糊回应（"嗯""再看看"）必须追问；**不得代替用户确认，不得把沉默当确认**。
3. **修改循环**：用户提修改意见 → 只改当前级 → 重新提交本级审批；改一次提交一次，直到明确通过，不得带病升级。
4. **未过审不生成**：大纲未过审，不写任何分集剧情；集剧情未过审，不生成该集提示词与工作流。宁可等待，不可预生成。
5. **级联作废**：上游改动作废下游——大纲修改后，受影响的集剧情状态重置为"待重审"；集剧情修改后，该集已生成的提示词/工作流作废重做。作废记录写入进度表。
6. **状态落盘**：每次审批结果实时写入《复刻-审批进度.md》；新会话接手时先读它，从第一个未过审层级继续——不重复生成已过审内容，也不跳过未完成的审批。
7. **一级一级推进（默认）**：第二级全部集剧情过审后，才进入第三级工作流生成；第三级内逐集生成、逐集交付。用户明确要求"边审剧情边出工作流"时，可对已过审的集提前放行，并在进度表标注。
8. **用户跳过审批**：用户明确说"跳过审批直接生成"时可以放行，但先提示风险，并在进度表标注"用户跳过审批"。

《复刻-审批进度.md》格式：

```markdown
# 复刻-审批进度

项目：<名称> ｜ 原视频：<路径> ｜ 复刻模式：<模式> ｜ 工作流模板：<模板名>

| 审批级 | 产物 | 状态 | 备注 |
|---|---|---|---|
| 第一级 剧情大纲 | 复刻-剧情大纲.md | ✅ 已确认 | — |
| 第二级 第1集剧情 | 复刻-第1集剧情.md | ✅ 已确认 | — |
| 第二级 第2集剧情 | 复刻-第2集剧情.md | 🔄 修改后待复审 | 服装改红色礼服 |
| 第三级 第1集工作流 | 复刻1.md / 复刻-工作流1.json | ⏳ 待生成 | — |
```

## 流程总览

```
参考视频文件
  → Step 0 元信息探测 + 提帧（ffmpeg / OpenCV）
  → Step 1 逐帧看图 → 《镜头分解.md》（事实依据）
  → Step 2 询问复刻模式（忠实复刻 / 风格迁移 / 单镜头）
  → Step 3 确认输出目录名
  → 【第一级审批】Step 4 生成《复刻-剧情大纲.md》→ 用户确认
  → Step 5 资产检索 → 《资产清单.md》
  → 【第二级审批】Step 6 逐集生成《复刻-第N集剧情.md》→ 逐集确认
  → 【第三级审批】Step 7 逐集生成《复刻N.md》+《复刻-工作流N.json》→ 逐集交付
  → Step 8 校验 → Step 9 合并（可选）
```

## Step 0 — 元信息与提帧（环境陷阱必读）

1. **元信息**：`ffprobe` 读分辨率、帧率、时长，判断横竖屏与总时长。
2. **提帧用本技能自带脚本，优先 ffmpeg、自动回退 OpenCV**：脚本会先探测 PATH 及常见位置的 ffmpeg，并用一个 32×32 黑帧 probe 验证该 ffmpeg 真的能写图片；验证通过才用 ffmpeg 提帧，否则自动回退到 OpenCV。本机存在两个 ffmpeg：TRAE 自带版（在 PATH，不能写 image2 序列）和录屏软件附带版（不在 PATH，能正常输出 png/jpg），脚本会自动选择能用的那一个。

   ```
   python <本技能目录>\scripts\extract_frames.py --video <视频路径> --out <输出目录> --interval 4 --height 480
   ```

   可选参数：
   - `--backend ffmpeg`：强制只找 ffmpeg，找不到就报错
   - `--backend opencv`：强制用 OpenCV

3. **提帧密度**：≤15s 视频每 2 秒一帧；15—60s 每 4 秒一帧；>60s 每 6—8 秒一帧。相邻帧内容突变处即疑似切镜点，可在两帧之间手动补 `--start` 再提一帧确认。
4. 帧图统一缩到高 480px 再看，节省 token。

## Step 1 — 镜头分解（复刻的事实依据）

用 Read 工具逐帧查看，`target` 写"视频第Ns画面，简述人物、服装、场景、动作、文字"，把观察结果填入《镜头分解.md》：

| 列 | 说明 |
|---|---|
| 镜头号 / 时间段 / 时长 | 由帧位置推断，内容突变即切镜 |
| 场景 | 地点、光线、背景物（品牌 logo 墙、豪车、人群、闪光灯） |
| 人物 | 人数、发型、妆容、配饰 |
| 服装 | 材质、颜色、剪裁细节，精确到"可照着重制"的程度 |
| 动作 | 每个镜头的核心动作（下车、走红毯、签名、挥手、回眸） |
| 镜头语言 | 景别（特写/半身/全景）、角度（仰拍/平拍）、运动（推/摇/跟随） |
| 画面文字 | 字幕卡、人物名牌、品牌 logo 墙、水印 |
| 内容/噪声判定 | 见下方规则 |

**噪声剔除规则**（录屏素材必查）：录屏软件水印、播放器 UI（进度条、时间戳、按钮）、平台图标、压缩伪影**不属于复刻对象**，在"画面文字"列标"噪声-剔除"；原视频自带的字幕卡、人物名牌、品牌 logo 墙属于内容元素，标"内容-复刻"，生成提示词时要写明文字内容、语言与位置。

分解表末尾写全片总结：色彩体系、平均镜头时长与转场节奏、贯穿母题/固定元素（如反复出现的品牌墙、同款字幕卡样式）、人物出场顺序表。

## Step 2 — 询问复刻模式（必须先问，不问不许生成）

| 模式 | 做法 | 适用 |
|---|---|---|
| 忠实复刻 | 人物、服装、场景、分镜全部按原视频 | 原视频人物有三视图资产，或用户自己有 |
| 风格迁移（默认推荐） | 保留分镜结构、镜头语言、节奏与氛围，人物/品牌换成用户自己的 | 无原人物资产，或规避版权 |
| 单镜头复刻 | 只挑 1—3 个镜头重做 | 试片、验证风格 |

用户未选时**主动推荐风格迁移**并说明理由，确认后再继续。

## Step 3 — 确认输出目录

正式输出前与用户确认目录名，默认：

```
d:\work\minimax_h3\<复刻项目名>\
```

目录内最终交付物：

```
镜头分解.md            Step 1 产物，全部剧情与提示词的事实依据
复刻-剧情大纲.md       第一级审批产物：全片故事 + 分集一览表 + 跨集锚点
复刻-第N集剧情.md      第二级审批产物：每集一份详细剧情，逐集过审
复刻-审批进度.md       三级审批状态表，随每次审批实时更新，跨会话恢复用
复刻N.md               第三级产物：每集完整 H3 提示词（该集过审后才生成）
资产清单.md            人物三视图路径与用途
复刻-工作流N.json      每集一份定制工作流（该集过审后才生成）
merge_segments.py      可选：H3 各集出片后用 ffmpeg concat 流拷贝合并成片
```

## Step 4 — 生成剧情大纲【第一级审批】

基于《镜头分解.md》与已确认的复刻模式，生成《复刻-剧情大纲.md》，内容五块：

1. **全片故事梗概**：原视频的完整叙事——人物、目标、冲突、结局。只写镜头分解表里看得到的事实，不脑补。
2. **复刻版故事映射**：忠实复刻 → 照搬原故事；风格迁移 → 写明替换后的人物/品牌，以及保留的分镜结构、镜头语言、节奏与氛围；单镜头复刻 → 只写所选 1—3 个镜头的故事。
3. **分集一览表**：集号 / 对应原视频时间段 / 时长 / 集标题 / 一句话核心事件 / 本集结尾钩子。按原视频天然镜头段落切，不硬切。
4. **跨集锚点**：固定色彩体系、字幕卡样式、贯穿道具/母题、人物造型延续。
5. **整体节奏与情绪曲线**：平均镜头时长、转场风格、情绪走向。

生成后**当场提交第一级审批**：在对话里呈现大纲（分集一览表必须完整展示），明确请用户确认或提修改意见。用户提意见就改，改完重新提交；获明确确认后在《复刻-审批进度.md》记录，才进入 Step 5。

## Step 5 — 资产检索与清单

大纲过审后人物清单已定，立即按人物名找三视图（同 `h3-drama-producer` Step 5）。本技能在**多台电脑上使用**，资产目录不固定，按候选列表依次探测，存在的目录都可用：

| 优先级 | 候选资产根目录 | 说明 |
|---|---|---|
| 0 | 用户当场指定的目录 | 永远最优先 |
| 1 | `D:\work\fanrenCharacter\` | 新资产库（新电脑） |
| 2 | `E:\短剧平台\凡人二创\人物图\` | 旧资产库（旧电脑），仍可使用 |

- **探测**：逐个候选根目录 `Test-Path` 判断是否存在，记下全部存在的根目录（一台机器上可能只有一个，也可能新旧并存）
- **检索**：对每个人物，在所有存在的根目录里按人物名匹配文件夹，再找三视图：

  ```powershell
  Get-ChildItem <根目录> -Recurse -Directory | Where-Object Name -like "*<人物名>*" | ForEach-Object { Get-ChildItem $_.FullName -Recurse -File -Filter "*三视图*" }
  ```

- 多个根目录都找到同一人物时：列出各处结果请用户选；用户不表态则取优先级最高的一处，并在清单中注明其余备选位置
- 找到后用 Read 工具查看图片内容，把实际形象写入清单
- 同一人物多张三视图时必须先问用户选哪张
- 忠实复刻模式下找不到原人物三视图：如实标注"未找到"，并给用户两条路——改走风格迁移模式，或先用生图工具为该人物做三视图再回来
- 输出 `资产清单.md`：人物、文件名、绝对路径、**来源根目录**、外观说明、与 <Picture N> 的对应关系
- **跨电脑迁移**：换电脑后《资产清单.md》里的绝对路径可能失效。接手旧项目时先逐条 `Test-Path`，失效条目按候选列表重新探测并更新清单（人物与外观不变，只换路径），已过审的剧情内容不动

资产就绪后，分集剧情与提示词里的服装描述一律以清单里的实际形象为准。

## Step 6 — 分集剧情【第二级审批，逐集进行】

逐集生成《复刻-第N集剧情.md》，每集包含：

- 集号 / 对应原视频时间段 / 时长 / 集标题
- **本集剧情详述**：起承转合小弧线——本集开场可独立理解、结尾有钩子或收束
- **镜头级内容表**：从《镜头分解.md》摘出本集全部镜头（场景/人物/服装/动作/镜头语言/画面文字），沿用"内容-复刻 / 噪声-剔除"标注
- **人物形象**：服装描述引用《资产清单.md》的实际形象
- **跨集衔接**：承接上一集的元素、留给下一集的钩子
- **声音与氛围**：需要的 BGM/人声情绪（按镜头分解的情绪描述对齐；录屏噪声不复刻）

逐集审批：生成一集 → 在对话里呈现该集剧情 → 用户确认或提修改 → 状态写入《复刻-审批进度.md》。该集过审前不生成其提示词与工作流；全部集过审后才进入 Step 7（用户明确要求边审边出工作流的除外）。

## Step 7 — 分集工作流【第三级审批，逐集生成】

只处理**已过审**的集。第一次执行前先做一次性决策：

**模板选择**：扫描 `d:\work\minimax_h3\工作流模板\` 列出模板并询问用户，选定后各集沿用。

然后逐集生成（对每个已过审的集，按顺序）：

1. 调用 `h3-prompt-writing` 技能生成《复刻N.md》（时长 4—15 秒灵活，按 Step 6 分集剧情确定的时长写作，时长体现在帧数与 0—Ns 时间线，不再区分 5/10/15 秒三档）

2. 提示词的人物服装、场景、动作、镜头语言必须与该集《复刻-第N集剧情.md》和《镜头分解.md》逐条对应，不得凭空想象
3. **画幅方向跟随原视频**：竖屏原片用 H3 竖屏画幅（768×1344 / 9:16），横屏用 1344×768；t8 模板走 ResolutionSelector 的 Portrait 档
4. 原视频画面内可见文字（字幕卡、名牌、logo 墙）写入提示词时保留原文与位置；噪声项（水印、播放器 UI）绝不入词
5. 忠实复刻时若原视频带背景音乐/人声且用户需要，声音设计按镜头分解的情绪描述对齐；录屏噪声（电流声、UI 音效）不复刻
6. 定制该集工作流 JSON（同 `h3-drama-producer` Step 6/7）：填提示词、锁定分辨率（竖屏片锁 768×1344）、设帧数、接 LoadImage 参考图槽、改输出前缀 `MiniMaxH3/<复刻项目名>`；提示词为 `h3-prompt-writing` 生成的 Ref2VA 六段结构，直接填入工作流节点；参考图经 runninghub 上传后回填文件名（上传链接仅一天有效）
7. 生成后用 computer:// 链接交付该集，在《复刻-审批进度.md》标记"已交付"；用户对成品提修改时只回改该集提示词/工作流，不波及其他集

## Step 8 — 校验清单（生成后必做）

- [ ] 镜头分解表"噪声"项（录屏水印、播放器 UI）未进入任何提示词
- [ ] 三级审批记录齐全：《复刻-审批进度.md》里大纲、每集剧情、每集工作流均有状态
- [ ] 所有生成了提示词/工作流的集都是已过审的集；未过审的集没有任何生成物
- [ ] 每集提示词与该集剧情文件、镜头分解表逐条对应（服装/场景/动作/镜头语言/画面文字）
- [ ] 画幅方向与原视频一致，分辨率已锁定
- [ ] 提示词 <Picture N> 引用与 LoadImage 数量、顺序一致；各集时间段无缺口覆盖 0—Ns
- [ ] T8 版六段结构齐全、[Shot N] 与时间戳格式正确、对白格式齐全
- [ ] 链路完整：links 两端互指一致、无悬空引用、被删节点无残留
- [ ] 帧数正确（5s→124 / 10s→243 / 15s→362）；last_node_id / last_link_id 已更新；JSON 可解析

## Step 9 — 成片合并（可选）

H3 每集最多 15 秒，超过 15 秒的原视频需要拆集生成，出片后再合并。若各集由**同一工作流模板、同一分辨率、同一编码参数**生成，优先使用 ffmpeg `concat` + `-c copy` **流拷贝**拼接：不重新编码、秒级完成、画质无损。

使用本技能自带的合并脚本：

```
python <本技能目录>\scripts\merge_segments.py --list segments.txt --out final.mp4
```

其中 `segments.txt` 每行写一集绝对路径：

```
file 'D:\work\minimax_h3\复刻项目\红毯复刻1.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻2.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻3.mp4'
file 'D:\work\minimax_h3\复刻项目\红毯复刻4.mp4'
```

注意事项：
- 各集分辨率、帧率、编码器必须一致，否则 `-c copy` 会失败或产生异常；脚本会先 probe 检查，不一致时拒绝并提示转码合并命令
- 如需加统一 BGM / 字幕，在合并后的成片上用 ffmpeg 或剪辑软件二次处理；合并脚本只做无损失的集间拼接
- 合并脚本同样继承 Step 0 的 ffmpeg 自动探测逻辑，找不到可用 ffmpeg 时回退到 OpenCV 软合并（慢且有损，仅应急）
