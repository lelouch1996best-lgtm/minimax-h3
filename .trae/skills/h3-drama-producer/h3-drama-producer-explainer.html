05 / STEP 1 — 2 剧本与分集

先分岔：成品剧本还是一句创意

完整剧本 → 直接落盘

已有场景划分、逐场动作、具体对白文本 —— 跳过创作，直接写入 <剧名>-剧本.md，进入分集。

创意 / 大纲 → 调用 story-craft

只有梗概和人物设定时，先按 H3 短剧容量定制写法创作剧本：每场对应未来一集，对白控制在 15 秒内说完，出场即给造型要点。

5 秒

单一动作 / 一个笑点

8 — 10 秒

一个小转折

12 — 15 秒

一次完整的关系变化

跨集衔接 A 衔接图先行：Step 4 先造衔接帧 → 出片可并行，但尾帧是预期值。 B 截取尾帧：E01 出片后截真实尾帧 → 衔接精准，但必须串行。
06 / STEP 3 — 4 元素识别与资产补全

找得到就引用，找不到就补 —— 但画风必须统一

角色三视图 + 造型 场景空镜 + 氛围 道具关键物特写
检索顺序 1 项目私有 <项目>\scene props 2 IP 共享 assets\<资源包>\ 3 备用源 如 凡人包 → 人物图\
缺失 → Step 4 四步走

① 先审批：整理缺失资产生成计划表格，用户批准后才动手
② 再生成：角色图生图锁脸改装，场景文生图空镜，道具特写
③ 人工核验：角色看身份锚点，场景看画风是否统一
④ 归档：三视图必归 IP 共享；场景道具按通用性判断

强制闸门 场景图与角色三视图画风不一致时，禁止直接使用。必须停下说明差异与风险、给出重绘 / 更换 / 书面确认三个选项 —— 2026-09《勾栏听曲》六集实测教训：Ref2VA 会按占画面更大的场景图统一风格，角色脸被「翻译」后五官走形。
07 / STEP 5 生成 H3 提示词

调用 h3-prompt-writing，按 Ref2VA 原生结构落笔

01subject_definitions 02summary 03retention_analysis 04detailed_description 05overall_soundscape 06non_diegetic_music
参考图先就位

保留分析照着实际图片写，与资产清单逐项核对，不留占位描述

衔接集换模式

改用 I2VA 首帧驱动，[Shot 1] 从首帧画面开始向前发展

格式约束

对白 <d>[语言]文本</d> + 说话人编号；时间线 0—Ns 无缺口

08 / STEP 6 选择提交方式

三条路，先读注册表再选

6A 应用 API

appId + 节点映射
nodeInfoList 覆盖节点字段，无需管理 JSON。常规批量出片首选（t8lite）。

6B 工作流直连

workflowId
直接用平台上已调好的 ComfyUI 工作流，参数改法与 6A 完全相同。

6C 模板工作流

模板 JSON
需要自定义节点图时用：锁死 1344×768、自己接多路参考图。

为什么读注册表 RunningHub API 查不到「我的收藏」—— 列表接口返回的是 7 万+ 条应用市场全量推荐，无法定位个人常用应用。 所以把常用 appId / workflowId / 模板登记在本地注册表里，用它当入口。
09 / STEP 7 — 8 上传图片与 payload 校验

两套上传接口，千万不要混用

6A · runninghub.upload_file

POST /openapi/v2/media/upload/binary
→ 返回 openapi/<hash>.png
填入 nodeInfoList 的 image 字段

6B / 6C · runninghub_app.upload_file

POST /task/openapi/upload
→ 返回 api/xxx.png
填入 LoadImage 的 widgets_values[0]

实测踩坑 6A 任务误 import 了 6B 的模块、把 api/ 路径写进 nodeInfoList，会在 LoadImage 报「No such file or directory」。 另外短路径写入工作区有分钟级同步延迟 —— 上传后秒提交同样会失败。
槽位引用与图片数量顺序一致
六段结构齐全 · 时间线无缺口
时长与分集表一致 · 帧数合法
保留分析与参考图实际内容一致
画风不一致 → 停止提交并提醒
方案 B 首帧槽为空是预期，标"待填"

提交方式：t8lite（6A 应用 API · plus）
参　　数：文戏 ｜ 15s ｜ 16:9 ｜ image1-4
预估费用：3 集 × ≈160 coins ≈ 480 coins
payload：E01-E03，每集提示词开头 100 字
→ 确认提交？或指定任一项调整。
default · 24G多图必 OOM
Ref2VA 多参考图不适用
plus · 48G≤ 10s 稳定
10s 以内必须用它；13s / 15s 必 OOM
ultra · 84G≥ 13s 必选
成本约 plus 10s 的 2.1 — 2.5 倍，不必先试 plus
两条铁律 账户同时最多 3 个任务（超限返回 421）；提交遇到挂起/超时 绝不立即重试 —— 任务可能已在运行，重试即重复扣费， 至少等 2—3 分钟再对账，已拿到 taskId 的一律续接不重提。
11 / 实测踩坑速查

这些坑，都已经写在 Skill 里了

01 画风冲突　场景图与角色三视图风格不一致时，Ref2VA 会把角色「翻译」成场景画风 → 五官走形，禁止带冲突提交
02 上传接口混用　6A 的 openapi/ 与 6B·6C 的 api/ 是两套接口，混用必在 LoadImage 报文件不存在
03 提交超时重试　超时不等于未送达 —— 立即重试就是重复扣费，等 2—3 分钟再对账
04 plus 跑 15 秒　48G 在单采样节点必 OOM，13s 以上直接上 ultra，省下十几分钟轮询
05 解析查询结果　results 是列表不是字典，按下标取 url，否则静默失败
06 跳过核验　每集下载后必须抽帧核验身份 / 场景 / 动作 / 无水印，才允许交付
